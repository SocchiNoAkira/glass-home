### P1. 备份导出→导入对称性破坏：共享图标引用的备份永远无法导入（数据陷阱）

| 字段 | 内容 |
|---|---|
| 严重度 | **高**（数据丢失风险；当前 UI 触发链受限，见影响范围） |
| 位置 | `src/infrastructure/persistence/backup.ts:50`（导出去重缺失）；`src/features/home/App.tsx:167`（复制共享引用）；`src/domain/workspace/schema.ts:160`（导入唯一性拒绝） |

**触发条件**：工作区中两个快捷方式共享同一 `iconAssetId`。两条路径可产生：
1. 对拥有上传图标的快捷方式使用编辑菜单“复制”（`duplicateShortcut` 的 `{ ...shortcut, ... }` 完整复制 `iconAssetId` 字段）；
2. 导入一份手工/未来版本构造的共享引用备份（该形态**通过**导入校验）后再导出。

**复现步骤**（`audit/integration.test.ts` 用例 “BUG CONFIRMATION: duplicating a shortcut that owns an iconAssetId produces an unimportable backup” 已完整执行证实）：
1. 快捷方式 A 设置 `iconAssetId: 'asset-1'`；
2. 复制 A 得到快捷方式 B（B 的 `iconAssetId` 同为 `'asset-1'`）；
3. 设置 → 数据 → 导出备份（成功，用户以为已有备份）；
4. 导入该备份。

**预期结果**：应用自身导出的备份可以导入恢复。

**实际结果**：
- `backup.ts:50` 的 `assetIds` 数组不去重，`exportBackup` 产出含两条 `id: 'asset-1'` 记录的 `assets` 数组；
- 导入时 `schema.ts:160` 的 `unique(ids)` 检查失败，抛出 **`备份中的资源 ID 不能重复。`** → 导入被拒绝，备份文件不可用。

**影响范围**：备份文件整体不可用。当前版本图标上传 UI 未实现（README 已声明），故普通用户操作暂不可直接触发；但 schema、复制逻辑、导出/导入链路均已就绪——**未来实现图标上传的当天即成为高危数据丢失陷阱**，且路径 2 当前即可触发。

**修复建议**（二选一或都做）：
- 在 `exportBackup` 收集 `assetIds` 后去重（`[...new Set(...)]`），使导出天然满足导入唯一性；
- 复制快捷方式时为副本生成独立 asset 或显式决定共享语义（若共享，导出仍必须去重）。

**验收**：`audit/integration.test.ts` 中该用例断言的是“当前缺陷行为”（导出含重复 + 导入抛错），修复后需反转为断言“导出 assets 无重复且 `validateBackup` 通过”。

## 2. 🟠 中严重度

### P2. 任何 `host:port` 输入都无法导航（端口支持整体是死代码）

| 字段 | 内容 |
|---|---|
| 严重度 | 中（核心功能失效，开发者高频输入） |
| 位置 | `src/domain/search/search.ts:35`（拦截）与 `:44`（不可达的端口分支） |

**触发条件**：搜索框输入任何字母开头的带端口地址，如 `localhost:3000`、`example.com:8080`。

**复现步骤**：搜索框输入 `localhost:3000` 回车（探针实测：`localhost:3000` → `仅支持安全的 HTTP/HTTPS 网址，不能打开此协议。`；`example.com:8080` 同样被拒）。

**预期结果**：导航到 `https://localhost:3000`（第 44 行裸域名正则中 `(?::\d+)?` 明确表明设计意图支持端口）。

**实际结果**：第 35 行协议前缀正则 `/^[a-z][a-z\d+.-]*:/i` 把 `localhost:`、`example.com:` 整段匹配为协议名，进入“拒绝危险协议”分支，第 44 行的端口支持**永远不可达**。对照：`192.168.1.10:9000` 走搜索引擎（IP 不匹配裸域名正则），行为不一致。

**影响范围**：所有字母开头的 `host:port` 输入。

**修复建议**：协议守卫应只拒绝**真正的非 http(s) 协议**。可在协议正则后追加排除：若形如 `host:port`（冒号后仅数字且整体匹配裸域名/localhost 模式）则走导航分支；或将裸域名判定前移到协议守卫之前。

**验收**：`audit/search.test.ts` 用例 `DEFECT: host:port inputs are refused by the protocol-prefix guard`（`it.fails`），修复后改回 `it`。

### P3. 自定义模板 `{query}` 位于主机位置时，多词/含斜杠查询静默失败

| 字段 | 内容 |
|---|---|
| 严重度 | 中（静默失败，无提示） |
| 位置 | `src/domain/search/search.ts:52-54`（不校验替换后 URL）；`src/features/search/SearchWidget.tsx:20`（忽略 `openSafeUrl` 返回值） |

**触发条件**：自定义搜索模板将 `{query}` 放在 authority/host 位置（如 `https://{query}.example.com/`——模板校验通过，因为校验用安全字面量 `'test'` 替换占位符），且查询含空格或 `/` 等字符。

**复现步骤**：① 设置自定义模板 `https://{query}.example.com/` 保存；② 搜索框输入 `hello world` 回车。

**预期结果**：模板被拒，或运行时给出错误提示。

**实际结果**：`resolveSearchDestination` 返回 `ok: true` 与 `https://hello%20world.example.com/`；该字符串经 WHATWG 解析 percent-decode 后主机含空格/斜杠，**不是合法 URL**（`new URL(...)` 抛 Invalid URL）；`openSafeUrl` 返回 `false`，而 `SearchWidget.tsx:20` 忽略该返回值 → **无导航、无消息**。

**影响范围**：使用 host 位置 `{query}` 自定义模板的用户，多词搜索必失败且无反馈。

**修复建议**：① `validateSearchTemplate` 拒绝 `{query}` 位于 authority 部分的模板（或至少给出警告）；② `resolveSearchDestination` 对替换后的最终 URL 再跑一次 `parseSafeHttpUrl`；③ `SearchWidget.submit` 检查 `openSafeUrl` 返回值，为 `false` 时 `setMessage('网址不安全或格式不完整。')`。

**验收**：`audit/search.test.ts` 用例 `DEFECT: host-position {query} + multi-word/slash queries ...`（`it.fails`），修复后改回 `it`。

### P4. 快捷方式增/改/复制/删除失败时无任何用户反馈（同步异常逃逸 `.catch`）

| 字段 | 内容 |
|---|---|
| 严重度 | 中（功能上限场景点击无反应） |
| 位置 | `src/features/home/App.tsx:161`（addShortcut）、`:167`（duplicateShortcut）、`:273`（removeShortcut）、`:156`（updateShortcut）；根因在 `src/domain/workspace/commands.ts:20-21` 等处同步 throw |

**触发条件**：网格满或达到数量上限时执行“添加/复制”快捷方式；或任何导致 `addShortcut`/`removeShortcut`/`updateShortcut` 同步抛错的情形。

**复现步骤**（探针实测）：对饱和网格调用 `addShortcut` → 同步抛出 `10 列网格中无法放置新图标：…`。关键机制：该异常发生在 `store.commit(addShortcut(workspace, ...))` 的**参数求值阶段**，早于 `store.commit` 被调用，因此 `.catch(() => undefined)` 无法捕获；`commitNow` 内部的 `setSaveError` toast 也未执行。

**预期结果**：toast 提示“网格已满，无法放置新图标”。

**实际结果**：事件处理器内未处理异常，控制台 uncaught error，用户无任何反馈。

**影响范围**：快捷方式 CRUD 全部入口。

**修复建议**：将领域命令调用包进 try/catch（或在 `store.commit` 接受 thunk），失败时 `store.reportError(error.message)`；不要仅靠 `.catch(() => undefined)`。

**验收**：手工或单测模拟 `addShortcut` 抛错路径，断言出现错误提示而非未捕获异常。

### P7. 编辑菜单“…”无法通过再次点击关闭（两处同模式）

| 字段 | 内容 |
|---|---|
| 严重度 | 中（编辑模式核心交互缺陷） |
| 位置 | `src/features/grid/EditBadges.tsx:66-79`（Widget 角标 `setOpen((value) => !value)`，`:71`）与 `src/features/shortcuts/ShortcutIcon.tsx:64`（`onMenu={() => setMenuOpen((open) => !open)}`）；根因在 `src/features/grid/EditMenu.tsx:41-42` |

**触发条件**：编辑模式点 "…" 打开菜单 → 再次点击同一 "…" 按钮。

**预期结果**：菜单关闭。

**实际结果**（事件链已核实）：`EditMenu.tsx:41-42` 的 document capture 阶段 `pointerdown` 监听器发现点击目标不在菜单内 → `onClose()` 卸载菜单（`open=false`）；随后触发按钮的 `click` 处理器执行 `setOpen(v => !v)`，此刻 `open=false` → 又置回 `true` → **菜单重新打开**。只能点击其他区域关闭。

**影响范围**：所有 Widget 角标菜单与快捷图标编辑菜单。

**修复建议**：触发按钮的 `pointerdown` 上做 `stopPropagation` 阻止冒泡到 document capture 监听器（注意 React 合成事件与原生监听器的关系，必要时用原生 `pointerdown` 监听处理），或在菜单关闭逻辑中识别触发按钮本身并跳过。

### P14. `SandboxDemo` iframe 双重加载；注释与实现不符

**问题**：React commit 时 JSX 的 `src` 触发首次加载，effect 中再次赋相同值触发第二次导航（赋值 src 即使值相同也会重新导航）。行为上沙箱握手仍工作（重试机制掩盖），但每次挂载加载两次；注释误导维护者以为 JSX src 已移除。

**修复建议**：删除 JSX 中的 `src` 属性，仅保留 effect 内的命令式赋值（与注释一致）。

### P15. `WidgetHost` 忽略 `enabled: false` 的内置组件

| 字段 | 内容 |
|---|---|
| 位置 | `src/features/widget/WidgetHost.tsx:32-71` |

**问题**：`builtin.clock/search/calendar/todo` 的分发分支直接 return，不检查 `instance.enabled`；`:67` 的 `instance && !instance.enabled` 分支只对**未知** instanceId 可达，而 schema 又禁止未知 widget（`schema.ts:132-136`）→ 该分支实际不可达。导入 `enabled: false` 的待办备份后，待办仍正常渲染（与校验语义不一致）。当前无 UI 入口设置 `enabled=false`，仅导入可构造。

**修复建议**：在各内置分支前统一检查 `instance?.enabled === false` 并渲染禁用卡片。

### P16. 桥接路由 `seenMessageIds` 无界增长

| 字段 | 内容 |
|---|---|
| 位置 | `src/infrastructure/widget-host/bridgeRouter.ts:53,106` |

**问题**：每个合法新 `messageId` 永久加入 `seenMessageIds` Set，仅 `close()` 清理。限流（20/秒）约束下约 72k 条/小时，长驻页面内存缓慢增长。

**修复建议**：限流窗口滚动时同步淘汰过期 messageId（时间桶/LRU 上限）。

### P17. `recordKey` 命名空间碰撞（架构性，当前不可触发）

| 字段 | 内容 |
|---|---|
| 位置 | `src/infrastructure/persistence/widgetStorage.ts:34-36` |

**问题**：存储键为 `${namespace}:${key}` 字符串拼接。namespace 含冒号时，`('a', 'b:c')` 与 `('a:b', 'c')` 产生同一键 `'a:b:c'`，`put` 互相覆盖、配额统计错位。schema 对 namespace 无字符集限制（`schema.ts:90`）。当前内置 namespace（`builtin.*`）无冒号，**当前版本不可触发**；第三方 Widget 开放后即成为真实数据覆盖风险。

**修复建议**：约束 namespace 字符集（禁止冒号）或改用结构化键/转义编码。

### P18. `solveLayout` 对 `move` 命令先校验 `target` 尺寸再改用 item 自身尺寸（API 契约陷阱）

| 字段 | 内容 |
|---|---|
| 位置 | `src/domain/grid/solver.ts:116-120` |

**问题**：`isValidSize(command.target, ...)` 在 target 被重建为 item 自身 w/h **之前**执行。调用方若传入与约束不符的 target w/h（尽管这些值最终会被忽略），命令被意外拒绝为 `no-placement`。当前全部调用方（`dragIntent.commandForIntent`、`keyboardCommand`）均传正确尺寸，未触发。

**修复建议**：move 语义下用 item 自身尺寸做校验（或将 target 尺寸校验限定于 resize），避免误拒。

### P19. `isBridgeRequest` 不校验 `payload` 的值（协议宽松点）

| 字段 | 内容 |
|---|---|
| 位置 | `src/domain/widget/bridge.ts:95` |

**问题**：仅检查 `'payload' in value`，值可为 `undefined` 或任意可 JSON 序列化内容（整体 64KB 预算仍生效）。当前 `environment.get` 不读 payload，故无害。

**修复建议**：未来新增方法时按方法分别约束 payload 形状；或至少拒绝 `undefined` 值。

### P20. zod payload 上限按字符数、配额按字节数（语义不一致，防线分层成立）

| 字段 | 内容 |
|---|---|
| 位置 | `src/domain/workspace/schema.ts:92`（`z.string().max(262144)` 按 UTF-16 字符数）vs `:207-212`（`payloadBytesOf` 按 UTF-8 字节数） |

**问题**：中文 1 字符=3 字节。单条 payload 字符数 ≤262144 但字节数超 256KB 时，zod 不拦截、由字节级配额兜底（审计测试已证实两层防线均生效）。属于纵深防御下的语义不一致，非漏洞。

**修复建议**（可选）：注释中说明两层各自语义，或将 zod 上限改为字节语义以消除歧义。
