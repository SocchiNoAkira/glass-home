## 目标与边界

1. 首发 macOS/Windows Chrome 与 Edge，使用 Manifest V3、本地 HTML 新标签页。
2. 时钟、日历、搜索、独立快捷图标和内置 Widget 共享统一整数网格。
3. 移动、交换、链式推挤、局部/全局重排、断点布局均为 P0；所有操作事务化，可撤销、重做、取消和失败回滚。
4. 本地优先、无账号、无行为统计、无远程可执行代码；可选能力按需授权。
5. 首版建议一个纯本地待办 Widget。天气、网络代理、书签导入、浏览器同步、Firefox/Safari 放 P1；多页、Dock、文件夹、Widget 市场及原生 macOS 容器不在首版。
6. 每阶段实现、自测、真实浏览器验收后暂停，待用户确认再推进。未完成项不得标为完成。

## 技术与模块

- WXT + Vite + React + TypeScript；pnpm lockfile 固定版本。
- Grid Engine 为纯 TypeScript，不依赖 React、DOM 或浏览器 API。
- UI 通过 application command 操作 Workspace；Persistence 不包含布局求解；Widget 不得直接写网格。
- IndexedDB 适配层承载 Workspace 与图片资源；单页面提交排队、导入原子替换、失败恢复。`expectedRevision` 与多页面冲突处理留到阶段 2B；首个正式 Workspace schema 为 v1，后续从 v2 开始实施版本迁移。
- Zod 已用于 Workspace 与备份运行时校验；正式第三方 Widget 清单与完整协议校验随阶段 3 实现。
- CSS 设计变量实现 Liquid Glass、明暗与四档降级，不声称原生逐像素一致。
- Vitest 已覆盖阶段 1 纯函数；fast-check 属性测试与布局求解器一同在阶段 2A 引入。Playwright 真实加载生产扩展验收。

```text
New Tab UI / Settings / Gallery
            |
  Application Commands & Store
            |
 Grid Engine | Workspace | Widget Host | Theme
            |
 Persistence | Permission Broker | Browser Adapter
            |
 IndexedDB / Browser APIs / Explicitly Authorized Network
```

**实现细节（原独立计划的技术决定，已并入此处以免丢失依据）**：
- 新命令形状为 `{ type: 'compact' }`，**不带** `instanceId` / `target`——整理是整页动作，不属于任何单个对象。
- `reflow` 的触发条件：推挤搜索返回空，且失败原因**不是** `budget-exceeded` / `cancelled` / 锁定冲突。预算耗尽不重试（重试只会再花一遍同样预算）。
- `reflow` 算法：固定拖动目标位与全部锁定对象 → 直接冲突对象先移出再加入待放置集 → 按阅读顺序逐个放置 → 候选区 x 覆盖全列、y 至 `layoutHeight + h + 3`（允许增加行）→ 每步计入预算 → 结果必须通过 `isValidConstrainedLayout` 全量校验。
- `compact` 排序键：面积降序 → 阅读顺序（y, x, order, instanceId）；逐个落进最靠上、最靠左的合法空位。保持图标相对顺序，不改尺寸、不动锁定对象，只写当前断点。
- 若整理结果与原布局完全一致 → `changes.length === 0` → `createLayoutPreview` 返回 `blocked`，UI 不得写入。

**实现细节（原独立计划的技术决定，已并入此处以免丢失依据）**：
- 待办数据模型：`{ id, text, done, createdAt, order }`；上限 **50 条**、单条文本 ≤ **120 字符**，超限拒绝并提示，**不静默截断**。
- 实例存储 key 格式 `${storageNamespace}:${key}`，每实例配额 **256 KB**，超限抛明确错误并显示配额不足卡片；与 `workspaceRepository` 分离，不共享事务。
- 错误隔离三条失败路径（脚本异常 / 加载超时 / 协议不兼容或权限拒绝）全部渲染错误卡片，保留网格位置，**不改变 `LayoutItem`**。
- 决策记录：待办是高频写，走 Workspace 会让每次勾选进布局撤销栈，语义错误，故使用实例存储。

**与早期计划的偏差（如实记录）**：早期计划写"示例 Widget 仅开发模式可挂载，生产构建不暴露入口"。实际实现是 `widget-probe.html` **已打包进生产包**并声明在 `manifest.sandbox.pages`，仅在设置「数据」页以 `allow-scripts` 内嵌展示；它没有 `web_accessible_resources`，外部页面无法直接访问。若要严格"生产不暴露"，需在构建时剔除该入口——**本轮未做**，属待决项。

## 数据与接口不变量

1. 每个实例恰好出现一次，坐标/尺寸为整数、不越界、不重叠。
2. 自动操作不移动锁定实例，不自动缩小对象。
3. 候选通过全量校验后才提交；预览和失败不得改变持久化状态。
4. 一次操作产生一个撤销事务；撤销恢复整个推挤链或整理结果。
5. 提交携带 expectedRevision；多页面冲突基于最新版本重放或提示，不静默覆盖。
6. Widget 使用宿主分配的会话与实例绑定，不信任自报 instanceId。
7. 大资源不同步；导入先完整校验，再预览和一次提交。

## 风险与回滚

- 求解复杂：确定性纯函数、属性测试、预算；失败保留原布局。
- 材质性能：限制模糊层，四档降级到实体高对比度表面。
- 存储失败：repository 单点提交，不显示已保存，可恢复最后合法快照。
- 多页面覆盖：草稿隔离和 revision 检查，不丢用户操作。
- 沙箱差异：P0 仅内置 Widget，第三方开发模式可独立关闭。
- 范围膨胀：多页/Dock/账号/市场不插入当前阶段。
- 构建兼容：依赖版本固定，升级前核对官方迁移说明和生产 manifest。

**接入点决策**：`ShortcutIcon` 只有抑制点击的 refs、无拖放入口，故拖放编排放在 `HomeGrid` 容器层事件委托（按 `data-instance-id` 定位被拖项），避免逐图标重复测量。`dragGeometry` / `dragIntent` / `keyboardLayout` / `gridMetrics` 等契约文件一行未改。

**两个不变量**：拖动开始时**固化布局快照**（预览会实时改写网格，若每次命中读当前布局，目标会跟着自己的重排漂移）；测量只在越过阈值时**执行一次**。

**修复的真实缺陷**：拖拽结束后残留的点击抑制会误吞下一次无关 UI 点击。Chromium 在多步拖拽后不总派发 `click`，标志位一直悬着吃掉了「撤销布局」点击。改为仅抑制落在网格内部的点击，且任何新 `pointerdown` 清零。**属产品层修复，未放宽断言。**

**补测覆盖缺口**：`dragGeometry` / `dragIntent` / `keyboardLayout` 三个 2B-1 核心纯函数此前零覆盖，补 34 项测试（52→86）。

**后续人工复核发现的三处视觉缺陷**（当轮自动化只断言 `data-*`，掩盖了问题；截图可读后暴露）：
1. `.drag-origin-slot` 缺 `position: absolute`，被当成额外网格项自动布局到无关格子（实测落在 x:728）；
2. 拖动元素同时被预览改到新格**又**叠加 transform，复合后偏离指针一整格（实测 121px）；改为拖动期间钉在原点，位移全由 transform 承担；
3. 拖动项 `z-index:6` 高于目标层 `4`，「交换」标签被自己盖住；标签改为目标层兄弟节点并抬到 `z-index:8`。

回归保护：feedback 用例新增 `elementFromPoint` 断言，确认标签是被绘制在最上层的元素，而非仅检查文字内容。

**截图路径**：改到本地 `/tmp/glass-home-shots`（可用 `GLASS_HOME_SHOTS` 覆盖），`captureViewport` 打印落点，不再写项目目录或依赖远程文件库。

**实现**：
- `compact` 命令与 `compact()`：锁定对象固定，其余按面积降序再按阅读顺序逐个落进首个空位；不改尺寸，结果必过全量校验。
- `reflow()`：仅在推挤返回空且失败原因非 `budget-exceeded`/`cancelled` 时触发；拖动位与锁定对象固定，其余贪心重放。预算耗尽与取消**不重试**（重试只会再花一遍同样预算）。
- `LayoutInspector` 增加紧凑整理入口（独立成行，整页动作不属于选中对象），预览展示影响对象数与页面高度变化（基线 6.11 要求）。

**14.2 的 20 项**：逐条具名映射到断言（`layout-acceptance-14-2.test.ts`），21 通过 + 2 显式 `skip` 并注明由哪个 Edge 用例真正覆盖（#14 Esc、#16 写失败）。**曾写过 `expect(typeof document === 'undefined').toBe(true)` 之类恒真断言冒充覆盖，已删除**——它只会让报告看起来更完整。

**修复/纠正**：
- **界面文案误导**：初版写"只压缩空白"，实测在默认 10 列影响 **20/23 个对象**（唯一空洞在 y=2 的 x=6..9，4 个图标填入后整行按阅读顺序前移）。算法符合 6.11，但文案须提示"会重排多数对象"。
- **撤销了一次多余的拖动重试**：曾给预览失败加"以 push-first 重试"。核实控制流后确认 `preference` 只影响空位与单对象交换两个快速路径，二者失败后都落到同一推挤搜索、其失败路径才是 reflow；该重试只会重复失败并清掉已有错误说明，已移除。

**关键决策**：待办数据**不进 Workspace**——勾选若走 Workspace 会 bump revision 并把"勾选"压入布局撤销栈，语义错误。数据库 v2→v3 增量创建 `widget-data` store，不重建已有 store。**沙箱只开放只读 `environment.get`**，网络/通知/书签/定位/实例存储一律不路由；一个能触达宿主的通道最容易长出"再加一个能力"的口子。

**最大风险与处理**：v2 校验要求每个内置 id 存在于三个断点，直接加待办会把**所有老用户送进恢复页**。`domain/workspace/migration.ts` 做增量迁移（只追加实例与各断点一个布局项），`load()` 中**先迁移再校验并写回**；未知未来版本拒绝而非降级。E2E 会真的把存储重写成 v1 再刷新，断言不落恢复页。

**修复的四个真实缺陷**：
1. **沙箱协议方向写反**：初版让宿主发请求、沙箱应答，而路由又校验"沙箱发来的请求"，自相矛盾，握手恒失败（实测面板停在"正在请求…"）。按基线 10.6 改为沙箱发起、宿主应答。
2. **默认布局被改坏**：初版把待办放在 `(6,2)`，把 20 个快捷方式整体下推一行，`github` 从 `(0,3)` 变 `(0,4)`，导致 2A 用例中 `(1,3)` 由"交换"变"移动"。改为与迁移同规则的 first-fit，把待办追加在**所有既有对象之后**（10 列落 `(0,5)`），既有对象一个不动。
3. 待办面板溢出压住下方图标（缺 `overflow` 裁剪）。
4. "清除已完成"渲染成白块（误用固定 28px 的 `.mini-button`，文字被压成竖排；且继承全局 `button` 外观）；删除按钮长期不可见（`opacity:0` 靠 hover 显现，无障碍陷阱，改常驻 0.45）。
