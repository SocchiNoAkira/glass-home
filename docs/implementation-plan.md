## 目标与边界

1. 首发 macOS/Windows Chrome 与 Edge，使用 Manifest V3、本地 HTML 新标签页。
2. 时钟、日历、搜索、独立快捷图标和内置 Widget 共享统一整数网格。
3. 移动、交换、链式推挤、局部/全局重排、断点布局均为 P0；所有操作事务化，可撤销、重做、取消和失败回滚。
4. 本地优先、无账号、无行为统计、无远程可执行代码；可选能力按需授权。
5. 首版建议一个纯本地待办 Widget。天气、网络代理、书签导入、浏览器同步、Firefox/Safari 放 P1；多页、Dock、文件夹、Widget 市场及原生 macOS 容器不在首版。
6. 每阶段实现、自测、真实浏览器验收后暂停，待用户确认再推进。未完成项不得标为完成。

## 技术与模块

- WXT + Vite + React + TypeScript；pnpm lockfile 固定版本。
- Grid Engine 为纯 TypeScript，不依赖 React、DOM 或浏览器 API。
- UI 通过 application command 操作 Workspace；Persistence 不包含布局求解；Widget 不得直接写网格。
- IndexedDB 适配层承载 Workspace 与图片资源；单页面提交排队、导入原子替换、失败恢复。`expectedRevision` 与多页面冲突处理留到阶段 2B；首个正式 Workspace schema 为 v1，后续从 v2 开始实施版本迁移。
- Zod 已用于 Workspace 与备份运行时校验；正式第三方 Widget 清单与完整协议校验随阶段 3 实现。
- CSS 设计变量实现 Liquid Glass、明暗与四档降级，不声称原生逐像素一致。
- Vitest 已覆盖阶段 1 纯函数；fast-check 属性测试与布局求解器一同在阶段 2A 引入。Playwright 真实加载生产扩展验收。

**技术依据（选型时的依据，不是事后补充）**：
- Chrome 官方支持 `chrome_url_overrides.newtab` 用本地 HTML 替换新标签页，并明确新标签页默认聚焦地址栏，不能依赖自动聚焦搜索框（基线 7.x 已据此约定页面不抢焦点）。
- Chrome `storage.local` 官方给出的默认总配额约 10MB，`storage.sync` 约 100KB、单项 8KB。故壁纸、图标缓存与 Widget 大数据不应放进 sync；统一走 IndexedDB 适配层以获得事务与配额控制。
- WXT 官方支持从配置生成 Manifest 并按浏览器目标输出；采用它能减少样板，但不把跨浏览器一致性当作框架自动保证，故阶段 4 仍需真机验收。
- 沙箱页的 CSP、资源加载与消息来源差异须通过最小扩展实证（阶段 0 已做），不以普通 iframe 演示代替。

**首个开发切片的思路**（已执行完毕，记录方法而非计划）：先做最小纵向闭环——最小扩展 → 本地新标签页 → 时钟/搜索/20 个图标 → 本地保存 → 真机验证；确认外观与扩展运行机制后，再集中投入最难的布局系统。首切片不碰第三方 Widget、联网搜索建议与跨浏览器同步。这一顺序在阶段 0/1 得到验证。

```text
New Tab UI / Settings / Gallery
            |
  Application Commands & Store
            |
 Grid Engine | Workspace | Widget Host | Theme
            |
 Persistence | Permission Broker | Browser Adapter
            |
 IndexedDB / Browser APIs / Explicitly Authorized Network
```

**实现细节（原独立计划的技术决定，已并入此处以免丢失依据）**：
- 新命令形状为 `{ type: 'compact' }`，**不带** `instanceId` / `target`——整理是整页动作，不属于任何单个对象。
- `reflow` 的触发条件：推挤搜索返回空，且失败原因**不是** `budget-exceeded` / `cancelled` / 锁定冲突。预算耗尽不重试（重试只会再花一遍同样预算）。
- `reflow` 算法：固定拖动目标位与全部锁定对象 → 直接冲突对象先移出再加入待放置集 → 按阅读顺序逐个放置 → 候选区 x 覆盖全列、y 至 `layoutHeight + h + 3`（允许增加行）→ 每步计入预算 → 结果必须通过 `isValidConstrainedLayout` 全量校验。
- `compact` 排序键：面积降序 → 阅读顺序（y, x, order, instanceId）；逐个落进最靠上、最靠左的合法空位。保持图标相对顺序，不改尺寸、不动锁定对象，只写当前断点。
- 若整理结果与原布局完全一致 → `changes.length === 0` → `createLayoutPreview` 返回 `blocked`，UI 不得写入。

**边界**：不做网络能力、不做第三方安装、不做刷新调度；布局与求解语义未改动。证据见本文档「验证与交付记录 · 阶段 3」。

**实现细节（原独立计划的技术决定，已并入此处以免丢失依据）**：
- 待办数据模型：`{ id, text, done, createdAt, order }`；上限 **50 条**、单条文本 ≤ **120 字符**，超限拒绝并提示，**不静默截断**。
- 实例存储 key 格式 `${storageNamespace}:${key}`，每实例配额 **256 KB**，超限抛明确错误并显示配额不足卡片；与 `workspaceRepository` 分离，不共享事务。
- 错误隔离三条失败路径（脚本异常 / 加载超时 / 协议不兼容或权限拒绝）全部渲染错误卡片，保留网格位置，**不改变 `LayoutItem`**。
- 决策记录：待办是高频写，走 Workspace 会让每次勾选进布局撤销栈，语义错误，故使用实例存储。

**与早期计划的偏差（如实记录）**：早期计划写"示例 Widget 仅开发模式可挂载，生产构建不暴露入口"。实际实现是 `widget-probe.html` **已打包进生产包**并声明在 `manifest.sandbox.pages`，仅在设置「数据」页以 `allow-scripts` 内嵌展示；它没有 `web_accessible_resources`，外部页面无法直接访问。若要严格"生产不暴露"，需在构建时剔除该入口——**本轮未做**，属待决项。

## 已实现能力（当前构建）

以下为截至 2026-11-17 构建实际具备的能力，供验收时对照；实现范围与偏差以各阶段记录为准。

- 本地 MV3 新标签页，离线打开时钟、日期、月历、搜索和快捷图标。
- 搜索与直接网址导航；自定义搜索模板及危险协议本地拒绝。搜索只在用户主动提交时访问所选服务，没有联网搜索建议。
- 20 个默认快捷图标，支持新增、编辑、复制、删除、文字/颜色回退；新增项在三个断点分别寻找合法空位。
- 时钟、搜索、日历和快捷图标共享 v1 整数网格数据模型；10/8/5 列独立布局。
- 编辑态目标格面板支持移动、交换、强制推挤、尺寸预设、锁定、预览、取消和撤销/重做。保存只影响目标断点；写入失败恢复旧布局。
- 指针拖放：普通模式与编辑模式均可拖动图标与 Widget。移动超过 6px 才算拖动，松手才提交；拖到图标本体为交换，拖到图标之间为插入推挤，拖到空白格为移动。**落点按按下时抓住的那一格对齐**（抓 Widget 中间拖动，目标格就跟着那一格走，而不是把对象左上角吸到鼠标所在格）。拖动中显示源位轮廓、目标格反馈与**按实测轨道生成的单元格参考网格**，`Esc` 或指针取消即回滚且不写入本地。
- 键盘布局：编辑模式下 `Tab` 选中对象后，方向键移动一格、`Alt+方向键` 调整尺寸；重排后焦点留在原对象。`Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 重做，输入框内的撤销不受影响。
- 普通点击打开网址；指针移动超过 6px 时抑制误导航；锁定对象既不能拖动也不能键盘移动。
- 主屏幕整体作为拖动表面：原生文本选择被关闭（`user-select: none`），输入框内仍可选词，避免从标签文字上起手时浏览器去拖选中的文字而不是图标。
- 推挤找不到位置时自动降级为**局部重排**（固定拖动位与锁定对象，不改尺寸）；两者都失败才回滚并说明原因。
- **紧凑整理（一键）**：按阅读顺序向上、向左压缩整页空白，大对象先定位、锁定对象保持原位、不改变任何尺寸。点一下即整理并保存，只记一个撤销事务；没有可压缩空间时提示「已经是紧凑排列」且不写盘。
- **编辑态只有拖动、键盘与底部按钮**：不再有「布局预览与事务」面板；底部固定为「整理 / 小组件 / 完成 / +」，普通模式为「小组件 / 编辑主屏幕 / +」。
- **预设快捷方式只在首次安装出现**：20 个预设是起始画面，之后（包括清除全部数据后重建）不再自动带回；日常只能通过「+」添加自己的快捷方式。显式的「恢复默认主屏幕 / 重建默认主屏幕」仍会带回预设。
- **内置待办组件**：回车添加、勾选完成、删除、清除已完成，50 条与 120 字符上限。数据存在按实例隔离的本地存储中，**不进入 Workspace**——勾选一件事不会产生布局事务，也不会污染布局撤销栈。
- **小组件可增删（iOS 风格）**：编辑态每个组件右上/左上各有一个角标，X 移除（二次确认，同时清除该组件保存的数据），"..." 里也有移除去；底部「小组件」按钮打开组件图库，列出本版本支持的四种内置组件，已放置的显示「已在主屏幕」，其余一键添加。添加时每个断点各自找第一个合法空位，尺寸与默认布局一致。
- **Widget 宿主**：每个组件包在独立错误边界内，任一组件崩溃只渲染错误卡片并保留网格位置，时钟、搜索、图标与布局引擎继续可用。组件通过宿主拿到主题、语言、尺寸、减少动态效果与材质等级。
- **沙箱组件通道**：设置 → 数据 → 沙箱组件通道可查看真实握手。沙箱页无法访问父页面 DOM 与扩展 API；宿主校验消息来源、实例绑定、重放与频率，仅开放只读环境能力。
- 明暗主题、四档材质、减少动态效果、时间/时区/日历、搜索引擎和打开方式设置。
- 自定义壁纸：原图不被内置渐变的装饰层覆盖；「背景模糊」作用在图片本身，「明暗遮罩」在深色主题下压暗、浅色主题下提亮，0% 即原图不做任何处理。
- Workspace v2 校验、IndexedDB 持久化、失败回滚、备份导入导出、本地壁纸与资源恢复。旧版 v1 数据在加载时自动增量迁移。
- 空快捷方式、损坏工作区恢复、原始数据导出、存储失败提示。
- 快捷方式显示站点真实图标：从浏览器**已缓存**的图标里读取（`favicon` 权限、`_favicon` 接口），扩展自身不发网络请求；浏览器没有缓存时保留文字首字母，访问过该站点后图标自动出现。
- 最小权限 Manifest（只有 `favicon`，无 `host_permissions`）；sandbox 父 DOM 与扩展 API 隔离，严格 CSP。

## 数据与接口不变量

1. 每个实例恰好出现一次，坐标/尺寸为整数、不越界、不重叠。
2. 自动操作不移动锁定实例，不自动缩小对象。
3. 候选通过全量校验后才提交；预览和失败不得改变持久化状态。
4. 一次操作产生一个撤销事务；撤销恢复整个推挤链或整理结果。
5. 提交携带 expectedRevision；多页面冲突基于最新版本重放或提示，不静默覆盖。
6. Widget 使用宿主分配的会话与实例绑定，不信任自报 instanceId。
7. 大资源不同步；导入先完整校验，再预览和一次提交。

## 风险与回滚

- 求解复杂：确定性纯函数、属性测试、预算；失败保留原布局。
- 材质性能：限制模糊层，四档降级到实体高对比度表面。
- 存储失败：repository 单点提交，不显示已保存，可恢复最后合法快照。
- 多页面覆盖：草稿隔离和 revision 检查，不丢用户操作。
- 沙箱差异：P0 仅内置 Widget，第三方开发模式可独立关闭。
- 范围膨胀：多页/Dock/账号/市场不插入当前阶段。
- 构建兼容：依赖版本固定，升级前核对官方迁移说明和生产 manifest。

**关键决策**

1. **`widgetData` 的 `undefined` 与 `[]` 必须区分**。`undefined` = 备份早于该字段（旧文件），导入时**保留**现存组件数据；`[]` = 备份确实没有数据，导入时**清空**。最初的 `validateBackup` 会把缺省补成 `[]`，导致导入旧备份静默删掉用户的待办——这是本轮发现并修掉的真实数据丢失缺陷。
2. **组件数据以 JSON 字符串原样往返**，不解析再序列化：存储里保存的就是这段文本，转一手会改变字节数，使配额判定与实际写入不一致。
3. **`WidgetStorage` 的操作串行化**。组件写入是 fire-and-forget（勾选不能阻塞 UI），于是"刚写完就导出"会读到旧数据、"刚写完就清除"会被迟到写入复活。加入内部队列后，导出与清除都排在已发起写入之后。
4. **沙箱 CSP 需 `'unsafe-inline'`**，与阶段 3 的收紧方向相反但原因充分：`sandbox.pages` 页面运行在 unique origin 下，`'self'` 不匹配任何资源，打包脚本被**静默阻止**（标签在、文件在、永不执行）。放宽仅限该已完全隔离的页面，`extension_pages` 未改动。

**本轮发现并修复的五个真实缺陷**

1. **备份完全不含组件数据**：`exportBackup` 只收集 `wallpaperAssetId` 与 `shortcut.iconAssetId`，恢复备份会丢掉全部待办。违反基线 14.3。
2. **`clear()` 只清 `workspaces`**：自定义图片与组件数据留在库中，"清除全部数据"名不副实，隐私声明不成立。违反基线 12.4。
3. **组件写入无串行化**：见上「关键决策」3。E2E 中复现为「写入后立即读库读到 0 条」。
4. **沙箱页脚本被 CSP 静默阻止**（既有缺陷，非本阶段引入）：`script-src 'self'` 在 unique origin 下匹配不到任何资源。定位过程见下「诊断方法」。
5. **沙箱握手存在两处竞态**（既有缺陷）：宿主在 iframe 已开始加载后才挂监听器；沙箱侧用 `requestAnimationFrame` 延迟发包，而实测该帧回调在沙箱 iframe 内**不触发**。改为「先挂监听器再赋 `src`」+「沙箱周期重试直至收到响应」。

#### 修复记录 · 拖动参考网格与真实轨道对齐（2026-11-17）

**问题**：普通模式拖动时背景显示的是 CSS 里写死的 24px 图案（`.unified-grid--dragging`），与真实轨道（分数列宽、92/82/76px 行高、14/10/4px 列间距）没有任何关系；编辑态的纹理也只画每列左边界，一个"方格"实际是「单元 + 一格间距」，比真实单元大。

- `background-origin: content-box`：纹理从第一列开始，而不是从 padding 边缘开始（窄屏编辑态有 padding）。

#### 实现记录 · 小组件可添加 / 可移除（2026-11-17）

**问题**：此前四个内置组件被 schema 硬性要求存在——`validateWorkspace` 会对任一缺失的内置组件抛错，`EditBadges` 因此刻意不给组件「X」，注释写明"提供一个只能失败的操作比不提供更糟"。用户要求按 iOS 的方式自由增删组件。

#### 实现记录 · 快捷方式显示站点图标（2026-11-17）

**需求**：快捷方式显示对应网站的真实图标，而不是文字首字母；取不到就保持文字，等用户打开过该站点之后再显示。

**三条路的取舍**：

| 方案 | 问题 |
|---|---|
| 自己 `fetch https://site/favicon.ico` | 需要 `<all_urls>` 主机权限；每个新标签页都会把配置里所有站点各请求一遍 |
| `<img src="https://site/favicon.ico">` | 不需要权限，但同样逐站点发请求，且无法判断站点到底有没有图标 |
| `_favicon` + `favicon` 权限（**采用**） | 多一个窄权限；但零网络请求，读的是浏览器已经缓存的图标，没有缓存就退回首字母 |

**实现**：

- `wxt.config.ts`：`permissions: ['favicon']`，`host_permissions` 仍为空。
- `src/infrastructure/favicon/siteIcon.ts`
  - 先按**精确页面 URL**取，再退回站点 origin：`_favicon` 是按页面 URL 建索引的，只访问过 `site.com/` 不会让 `site.com/app` 有图标。
  - `fetch` 读回字节，与"不存在的页面"返回的默认地球图标逐字节比对。Chromium 对没有缓存的站点也返回 200 + 默认图标，不比对的话所有未访问站点都会变成同一个灰地球（比首字母更糟）。
  - 结果按图标 URL 缓存，20 个快捷方式不会在每次渲染时重复读字节。
- `ShortcutIcon`：先渲染首字母，解析成功后整体替换为 `<img>`（不闪烁、不出现默认图标）；`onError` 回退首字母。
- 尺寸取 **32px**：实测请求 64px 时，只缓存了 16px 位图的站点会被回以默认图标；32px 显示在 56px 磁贴的 66% 区域，放大有限。

**两个实测得到的坑（已写进测试注释）**：

1. `_favicon` 以页面 URL 为键，不是主机；origin 兜底是必需的。
2. 只有 `<img>` 能解码、但 CRC/zlib 不合规的 PNG **不会**进入浏览器图标库——图标测试如果用手拼的 base64，会误判「取不到图标」。用例改为在 Node 里用 zlib 现场生成合法 PNG。

**验证**：新增 4 项单测（候选顺序：精确页 → origin、同源只问一次、去 fragment、拒绝非 http）；新增 E2E `stage-4-icons`：本地 HTTP 站点先访问一次 → 快捷方式显示真实图标且不再有首字母，从未访问的域名保持首字母。`tsc` 通过；Vitest **255 通过 + 2 跳过**；无窗口全量 E2E **46 项 1 轮全通过**。

**权限变更的连带更新**：`docs/privacy-and-permissions.md` 从"无任何权限"改为"只有 `favicon`"，并说明图标不落库、不进备份；`stage-1-assets-security` 的 manifest 断言改为 `permissions: ['favicon']`、`host_permissions: []`。

## 手动验收清单（阶段 4 重点）

自动化覆盖了功能回归，但以下属于**人工判断**，自动化替代不了。按顺序做一遍，每步都能独立回退。自动化范围与最近一次运行结果见本文档「验证与交付记录」。

### 准备：加载扩展

```bash
pnpm install        # 首次
pnpm build          # 必须：E2E 与手动验收都读 .output/chrome-mv3
```

Edge 打开 `edge://extensions` → 开启「开发者模式」→「加载解压缩的扩展」→ 选 `.output/chrome-mv3`。新开一个标签页（或按新标签快捷键）即进入 Glass Home。

> 只加载 `.output/chrome-mv3`。`pnpm dev` 生成的 `.output/chrome-mv3-dev` 含 `ws://localhost:3000` 热更新客户端，开发服务器没在跑时会在扩展错误页报 WebSocket 握手失败与 `[wxt] Failed to connect to dev server`——那是开发模式未连上，不是产品缺陷。

> 想用打包产物验证，可先在 `edge://extensions` 里卸载，再用 `.output/glass-home-0.1.0-chrome.zip` 解压后的目录加载——两者内容一致。

### ① 备份带回组件数据（基线 14.3）

1. 在待办里加 2 条，勾选其中 1 条。
2. 设置 → 数据 → **导出备份**，保存到桌面。
3. 打开该 JSON 文件，搜索 `widgetData`，应能看到 `"namespace": "builtin.todo"`。
4. 设置 → 数据 → **清除全部数据** → 二次确认 → 页面自动重载，待办应为空。
5. 设置 → 数据 → **导入备份**，选刚才那份 → 待办内容与勾选状态应**完全恢复**。

**判断点**：第 5 步恢复的是「2 条，其中 1 条已完成」，不是「2 条都未完成」。

### ② 清除单个组件（基线 12.4）

1. 待办里留几条内容。
2. 设置 → 数据 → 组件数据列表，「待办」那行应显示**真实占用**（不是 0 B）与「清除」按钮。
3. 点「清除」→ 二次确认 → 待办内容清空，但**待办组件本身还在原位**，周围图标位置不变。
4. 刷新页面，确认清空是持久的。

**判断点**：组件消失或位置变化都算失败——清除的是「数据」，不是「组件」。

### ③ 清除全部数据要真的清干净（基线 12.4）

1. 设置里换一张自定义壁纸。
2. 加点待办。
3. 设置 → 数据 → **清除全部数据** → 二次确认。
4. 页面重载后：壁纸回到默认渐变、待办为空、**快捷方式为 0**（预设只在首次安装出现，清除后不应回来），四个组件仍在。

**判断点**：若壁纸还在，说明 `assets` 没被清；若待办还在，说明 `widget-data` 没被清；若 20 个预设快捷方式又出现，说明种子标记失效。

### ④ 旧备份不能误删待办（最难发现的一类缺陷）

1. 先按 ① 的步骤 2 导出一份**当前**备份。
2. 用文本编辑器打开它，删除整个 `"widgetData": [...]` 字段（注意逗号），另存为 `legacy.json`。
3. 保留页面现有待办不受影响的前提下，导入 `legacy.json`。
4. **待办应仍然存在**。

**判断点**：这是一条数据丢失防线。「备份里没有这个字段」不等于「用户没有数据」，二者必须区分。

### ⑤ 沙箱通道（阶段 3 的既有缺陷修复）

设置 → 数据 → 滚到底部「沙箱组件通道」：

- 状态应为「已取得环境：深色 · zh-CN · balanced」，**不是**「沙箱未在时限内请求环境信息」。
- 下方小窗内显示主题/语言/尺寸/减少动态/材质五行。

**判断点**：曾经这里是稳定超时。若又出现超时，是回归。

### ⑥ 布局与键盘（阶段 2B 回归）

1. 进入编辑模式，用鼠标把一个图标拖到另一个图标上（交换）、拖到两图标之间（插入推挤）。
2. 拖动过程中按 `Esc`，布局应回滚且不写入本地。
   - 从图标下方的文字标签上起手拖动，页面不应出现蓝色文字选中；搜索框内仍能正常选词。
3. `Tab` 选中对象后方向键移动一格、`Alt+方向键` 改尺寸，重排后焦点仍在该对象。
4. `Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 重做。
5. 普通模式拖动时，背景参考网格的方格应与落点单元格同尺寸，间距保留为缝隙。
6. 抓住日历或时钟的中间（不是左上角）拖动：预览框应始终压在对象自己身上，松手后对象落到的位置与拖动时的观感一致；原地小幅晃动不应产生移动。
7. 进入编辑模式：**不应出现**「布局预览与事务」面板；底部应为「整理 / 小组件 / 完成 / +」。点「整理」应立即整理并保存，`Ctrl/Cmd+Z` 一步恢复；再点一次应提示「已经是紧凑排列」且不产生新的保存。

### ⑦ 视觉与无障碍（自动化无法判定）

- 设置一张自定义壁纸：整页应只显示这张图，**没有**彩色光斑、光带、上下渐变或额外的提亮；把「背景模糊」拉到最大应明显变虚，把「明暗遮罩」在 0% 与 70% 之间拖动应有明显的明暗差异。
- 四档材质（高/均衡/低/关闭）逐个切换，确认**差异真实可见**，关闭档应是实体表面而非仍带模糊。
- 浅色/深色 × 三种渐变壁纸，检查文字对比度是否够读；浅色模式整体应偏柔和的粉紫/苔绿，**不应发白刺眼**，白色玻璃面要与背景分得开。
- 系统开启「减少动态效果」后，拖动过渡动画应消失。
- 把窗口从 1440 拖到 1200、900、700 宽，检查是否出现横向滚动条。
- 全程纯键盘操作一遍，确认焦点不会丢失、不跑进被遮挡区域。

### ⑧ 小组件增删（iOS 风格）

1. 进入编辑模式：每个组件左上角应有 ×，「...」菜单里也应有「移除小组件」。
2. 移除「待办」→ 二次确认 → 组件消失；刷新后仍然没有，且原来的待办内容已被清除。
3. 底部「小组件」→ 图库中已放置的类型显示「已在主屏幕」，其余可点「添加」；把待办加回来，应出现在第一个空位且清单为空。
4. 把窗口缩到 8 列、5 列，确认加回来的组件在这两个断点也各自落在合法位置（不与其它对象重叠）。

**判断点**：移除后刷新若组件又出现，说明只改了显示没落盘；加回来后待办内容仍在，说明移除时没有清数据。

### ⑨ 站点图标

1. 新建一个指向你常去站点的快捷方式。若浏览器此前从未打开过该站点，磁贴应保持**文字首字母**。
2. 打开该站点一次，回到新标签页刷新：应显示站点真实图标；从未访问且无图标的站点（例如随便编的域名）仍保持首字母。
3. 打开 `edge://extensions` 看该扩展的权限：不应出现「读取和更改您在所有网站上的数据」这类主机权限。

**判断点**：所有未访问站点都变成同一个灰色地球，说明默认图标没有被过滤；图标永远是字母，说明权限或 32px 尺寸那条路径坏了。

### 已知不算缺陷的现象

- 清除全部数据后会**整页重载**，此时正在编辑的未提交布局会丢——这是设计取舍。
- 待办勾选**不会**产生撤销记录（数据不进 Workspace，这是刻意的）。
- 撤销历史只保留在当前页面内，刷新即清空。

## 跨阶段未完成清单（汇总）

以下项目在所有已实现阶段中**均未完成**，不作为任何阶段的完成项：

1. **缺失功能**：网络代理与 Permission Broker；通知/书签/定位；第三方 Widget 安装、刷新调度、市场与签名分发；横向多页、Dock、文件夹；账号与云同步；独立图片图标上传；Widget 指针拖拽尺寸手柄。
2. **"保持分组"整理模式未做**：默认布局无 `groupId`，实现后恒为空操作。
3. **多页面 `expectedRevision` 冲突**：当前为单页面主屏幕，无第二页面。
4. **性能**：60fps 目标、持续拖动与长任务检测未测量；只有零散的诊断样本，不构成承诺。
5. **无障碍**：完整屏幕阅读器流程、全部壁纸组合的 WCAG 对比度未验收（基线 8.6 / 14.5）。阶段 4 仅在数据管理新增了 `forced-colors` 回退与键盘可达入口。
6. **跨浏览器**：Chrome 未安装（阶段 4 未测）；Edge 已在 macOS（阶段 0–4 历史记录）与 Windows（2026-11-17，无窗口运行 7 个相关用例）执行过，**Windows 全量回归未跑**；Firefox/Safari 未实测；基线 14.6 的「Chrome + Edge」要求尚未满足。
7. **撤销历史**：仅存当前页面内存，不跨刷新；普通快捷方式 CRUD 不是布局历史事务。
8. **沙箱示例页仍在生产包内**：`widget-probe.html` 由 manifest 声明为 sandbox 页并在生产构建中输出；它无 `web_accessible_resources`，仅内嵌使用。若要严格做到"生产不暴露开发示例"，需在构建时剔除该入口——**未做**。
9. **备份跨设备迁移未验证**：备份文件可在不同浏览器配置文件间导入的设计成立（纯本地 JSON），但只实测了同一 profile 内往返。
10. **组件数据备份依赖存储已打开**：导出前若 `WidgetStorage` 尚未 open，会以「组件存储尚未就绪」明确失败而不是静默导出空数据；该失败路径未做 E2E 覆盖。
11. **Workspace 迁移**：当前为 v2（v1 加载时自动增量迁移）；后续任何 schema 变更都必须继续提供迁移路径，否则既有用户会落到恢复页。

## 文档职责划分

- `README.md`：**面向使用者的最小说明**——这是什么、怎么装、怎么跑、文档在哪。不写进度、不写验收步骤、不堆能力清单。
- `docs/implementation-plan.md`（本文件）：**唯一进度真相来源**，含阶段计划、已实现能力清单、实施记录、测试运行方式、手动验收清单、验证结果与未完成清单。
- `docs/product-baseline-v1.md`：需求基线（章节号如 6.9 / 6.11 / 10.x / 14.2 均指向此处）。
- `docs/adr/0001-stage-0-foundation.md`：阶段 0 技术决策。
- `docs/grid-state-machine.md`：网格状态机草案。
- `docs/compatibility-matrix.md`：仅记录实际测试过的浏览器组合。
- `docs/privacy-and-permissions.md`：面向使用者的权限与隐私说明（阶段 4 交付，随版本更新）。
