# Glass Home：权限与隐私说明

适用于版本 **1.0.0**（`glass-home-1.0.0-chrome.zip`）。本文只陈述**已实测或可在构建产物中核对**的事实；未验证的行为不作承诺。

## 一句话结论

Glass Home 是一个**纯本地**新标签页：只申请 `favicon` 一项权限，不联网，不收集数据，不包含远程可执行代码。所有设置、布局、快捷方式、自定义图片和组件数据只保存在你所用浏览器的本地 IndexedDB 中。

## 申请的权限：只有 `favicon`

生产构建的 `manifest.json` 中：

```json
"permissions": ["favicon"],
"host_permissions": []
```

核对方式（解压发布包后）：

```bash
unzip -p glass-home-1.0.0-chrome.zip manifest.json | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['permissions'], d['host_permissions'])"
# 预期输出：['favicon'] []
```

`favicon` 只做一件事：允许扩展读取**浏览器自己已经缓存好的网站图标**（`chrome-extension://<id>/_favicon/?pageUrl=…`），用来把快捷方式的文字首字母换成真实图标。它不授予访问网站内容的权力，扩展也不会因此获得任何网络请求能力。

由此可推出的范围限制：

- 不能读取浏览历史、书签、剪贴板、下载记录或其它扩展的数据（`favicon` 不是 history 权限，只能按你已配置的快捷方式 URL 取图标）；
- 不能读取你在任何其它网站上的内容；
- 不会获得常驻后台能力（扩展没有 background service worker 的敏感权限）；
- 不能发起需要额外授权的系统能力（通知、定位等）；
- **没有 `host_permissions`**，所以扩展不能自己请求任何站点。

## 网络请求

**不发起任何网络请求。** 具体边界：

| 场景 | 行为 |
|---|---|
| 打开新标签页 | 无请求（页面资源全部打包在扩展内） |
| 时钟、日历、待办 | 无请求（本地计算） |
| 快捷方式图标 | 无请求：向浏览器读取它**已经缓存**的该站点图标；浏览器没有缓存时保持文字首字母，等你打开过该站点后图标才会出现 |
| 点击搜索 | 浏览器按你选择的搜索引擎跳转一次（这是你主动发起的导航，不是扩展的后台上报） |
| 联网搜索建议 | **默认关闭**，且当前版本未实现该功能 |
| 天气 | 未实现（计划中为手动选择城市，不默认定位） |
| 壁纸 | 本地绘制或你本地选择的文件 |

## 数据保存位置与内容

保存在浏览器为该扩展分配的 IndexedDB（数据库名 `glass-home`），共三个对象仓库：

| 仓库 | 内容 | 是否进入备份 |
|---|---|---|
| `workspaces` | 设置、三个断点（10/8/5 列）的布局、快捷方式元数据、组件实例声明 | 是 |
| `assets` | 你选择的本地自定义壁纸（≤4MB），以 Blob 存储 | 是 |
| `widget-data` | 每个组件实例自己的数据（如待办清单），按实例命名空间隔离 | 是 |

**不保存**：浏览历史、书签、账号信息、位置、遥测、广告标识符。

**快捷方式图标不由 Glass Home 保存**：它直接读取浏览器的图标缓存，不写入本扩展的数据库，也不进入备份文件。因此换一份浏览器配置时，图标要等你在新配置里访问过对应站点才会重新出现；快捷方式本身（标题、网址、颜色）不受影响。

## 你拥有的控制权

设置 →「数据」页提供四个明确入口：

1. **导出备份**：生成 JSON 文件（含设置、布局、快捷方式、壁纸与组件数据）。导出在本地完成，文件不会上传。
2. **导入备份**：读取你选择的 JSON 文件。导入前完整校验；导入为一次原子替换。
3. **清除单个组件数据**：只删除该组件的本地内容，组件与布局位置保留。
4. **清除全部数据**：删除工作区、自定义图片与全部组件数据，并重建空白主屏幕，需要二次确认。

> 备份文件是一份包含你个人配置的明文 JSON。若你将它发送给他人，对方可以读到你保存的快捷方式与待办内容。

## 沙箱开发示例页（`widget-probe.html`）

发布包内包含一个用于验证组件隔离通道的开发示例页，由 manifest 的 `sandbox.pages` 声明。它：

- 以 `<iframe sandbox="allow-scripts">`（**不含** `allow-same-origin`）嵌入，只在你打开设置「数据」页时加载；
- **无法**访问父页面 DOM、扩展 API 或任何来源绑定的存储；
- 只能向宿主请求一项只读能力：主题、语言、尺寸、减少动态、材质档位；
- 无 `web_accessible_resources` 声明，外部网页无法引用它。

该页存在于生产包中，但它不构成数据访问面；若将来严格剔除开发示例页，会在构建配置里移除该入口。

## 内容安全策略（CSP）

```text
extension_pages: script-src 'self'; object-src 'none'; base-uri 'none';
sandbox:     sandbox allow-scripts; script-src 'self' 'unsafe-inline'; object-src 'none'; base-uri 'none'; default-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'none';
```

两处要点：

- `connect-src 'none'` — 页面内无法发起任何网络请求，这是"不联网"在浏览器层面的强制，而不只是代码里没写。
- 沙箱页的 `script-src` 含 `'unsafe-inline'`。原因是：`sandbox.pages` 的页面运行在 unique origin 下，`'self'` 不匹配任何资源，否则打包脚本会被**静默阻止**。该页已由 `sandbox="allow-scripts"` 完全隔离，无法触达宿主，因此这里的放宽不产生跨边界风险。

## 已知限制

- **仅实测 Microsoft Edge 157.0.4341.42**。Chrome、Firefox、Safari 未实测，不作支持承诺。
- 不提供账号、云同步、跨设备迁移。
- 数据只存在于**当前浏览器配置文件**。清除浏览器数据、删除扩展或更换浏览器配置文件都会丢失数据；请自行导出备份。
- 使用不同的浏览器（例如 Chrome 与 Edge）时，各自是独立的一套本地数据。
- 卸载扩展会连同其 IndexedDB 一起被浏览器清理 —— 请先导出备份。

## 不构成承诺的部分

- 不声称符合任何特定隐私认证或合规标准（如 GDPR、CCPA 的特定条款）。
- 不声称具备不可被本地管理员审计的加密存储：数据以明文形式存放在浏览器配置目录内，能访问该目录的人可以读取。
- 不提供遥测开关，因为不存在遥测。
