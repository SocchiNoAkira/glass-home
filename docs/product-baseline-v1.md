## 1. 文档约定与需求结论

### 1.1 需求优先级

- **P0**：首个可用版本必须完成。
- **P1**：核心版本稳定后完成，但接口和数据结构需提前预留。
- **P2**：增强功能，不阻塞首发。

### 1.2 核心产品定义

Glass Home 是一款桌面浏览器扩展，以本地 HTML 页面替换浏览器新标签页。页面以 iPad 主屏幕的混排和编辑方式为交互参考，以 macOS 锁屏的信息层级为默认视觉构图，并采用 Apple Human Interface Guidelines 的材质、同心圆角、排版和辅助功能原则。

核心能力如下：

1. 时钟、日期、日历、搜索和网页快捷方式。
2. 默认提供两行各 10 个快捷图标，但每个图标都是独立网格对象。
3. 快捷图标与小组件在同一画布中自由混排。
4. 所有对象遵循统一网格，最终布局不得互相覆盖。
5. 支持空位移动、自动推挤、链式推挤、位置交换、局部智能重排、全局智能整理和断点自适应重排。
6. 支持事务化布局操作、撤销、重做、取消、锁定和失败回滚。
7. 提供可版本化、可隔离、可授权的小组件开发接口。
8. 默认本地优先，不依赖账号，不默认收集浏览或搜索行为。
9. 通过 Web 技术模拟 Liquid Glass；普通浏览器扩展不承诺直接嵌入 macOS 原生控件。

### 1.3 “接近 iPad 主屏幕”的具体含义

本项目参考的是以下交互特征，而非完整复制 iPadOS：

- 图标与组件混排；
- 单击打开、拖动布局；
- 插入时其他对象让位；
- 图标之间可交换；
- 不同尺寸组件参与统一布局计算；
- 编辑模式下显示删除、尺寸和锁定操作；
- 平滑但克制的位移反馈。

横向多页、文件夹和底部 Dock 不因这一描述自动进入 P0，见第 16 节。

### 1.4 关键设计决策

- 快捷方式不是整体工具栏，而是独立图标实例。
- 页面只存在一个统一布局引擎，搜索框和内置组件也不能绕过。
- 普通拖动只允许局部自动重排；全局整理必须预览并确认。
- 智能重排采用确定性的约束和评分算法，不依赖生成式 AI。
- 布局计算先在副本上完成，全部验证通过后一次提交。
- 第三方 Widget 默认运行在沙箱中，不能直接访问扩展 API 或其他组件。
- 默认拒绝远程可执行代码，核心资源随扩展本地打包。

## 2. 产品范围与平台策略

### 2.1 首发范围

推荐首发平台：

- macOS 与 Windows 上的 Chrome、Edge；
- Manifest V3；
- 桌面窗口和桌面输入方式；
- 新标签页覆盖。

第二阶段适配：

- macOS Safari；
- Firefox；
- 不同浏览器的存储、权限、后台调度和 CSP 差异。

### 2.2 新标签页、主页和启动页

浏览器扩展最稳定的能力是覆盖新标签页，它不必然同时改变：

- 浏览器启动时打开的页面；
- 点击主页按钮时打开的页面；
- 已经存在的网页；
- 浏览器设置页。

因此产品定义为“新标签页扩展为主，主页按钮与启动页配置为辅”。各浏览器支持情况必须写入兼容矩阵，不作跨浏览器一致性的虚假承诺。

### 2.3 P0 不包含

- 修改普通网页样式；
- 在线账号和云端服务；
- 公开 Widget 商店；
- 强制自动聚焦页面搜索框；
- 永久后台运行或精确到秒的后台任务；
- 任意重叠、自由旋转和 z 轴层级编辑；
- 在浏览器 DOM 中直接使用 AppKit/SwiftUI 原生 Liquid Glass 控件；
- 未经用户授权的浏览历史、书签、定位和搜索建议。

## 3. 信息架构与默认页面

### 3.1 页面层级

| 层级 | 内容 | 规则 |
|---|---|---|
| 背景层 | 壁纸、渐变、调暗或提亮遮罩 | 不参与网格，不响应拖动 |
| 内容层 | 时钟、日历、快捷图标、内容型 Widget | 统一网格，逻辑上不重叠 |
| 功能层 | 搜索框、编辑、添加、设置等控件 | 使用 Liquid Glass 风格 |
| 弹层层 | 菜单、设置、搜索建议、确认框 | 可临时覆盖，不占网格 |
| 状态层 | 拖动预览、推挤提示、错误和加载状态 | 不修改布局直到事务提交 |

### 3.2 默认布局顺序

首次安装建议从上到下排列：

1. 时钟与日历信息区；
2. 搜索框；
3. 两行各 10 个快捷图标；
4. 推荐小组件；
5. 悬浮编辑、添加和设置入口。

这只是初始坐标方案。进入编辑后，图标可以插入组件之间，组件可以放在图标左侧、右侧或下方，也可以保留空白位置。

### 3.3 主屏幕与设置页

主屏幕负责高频操作：查看时间、搜索、打开网页和使用 Widget。复杂设置应放在独立设置页或弹层中，包括：

- 外观与壁纸；
- 搜索；
- 时间和日期；
- 网格与重排偏好；
- Widget 管理和权限；
- 数据同步、导入、导出和清除；
- 浏览器权限说明。

## 4. 内置功能规格

### 4.1 时钟组件（P0）

- 小时、分钟；秒显示可选。
- 12/24 小时制。
- 使用系统时间、语言和地区格式。
- 可指定时区。
- 日期和星期可独立显示或隐藏。
- 使用等宽数字特性，避免时间变化引起宽度跳动。
- 默认按分钟更新，只有显示秒时提高刷新频率。
- 页面不可见时暂停非必要刷新。
- 支持至少两种网格尺寸，并声明最小可读尺寸。

### 4.2 日历组件（P0）

- 日期、星期和月份显示。
- 紧凑日期模式与完整月历模式。
- 上一月、下一月切换。
- 今天高亮。
- 每周第一天可配置。
- 农历和节假日作为可选数据扩展，不默认联网。
- 日历事件和系统日历读取列入 P1/P2，需要单独权限评估。

### 4.3 搜索组件（P0）

- 内置 Google、Bing、百度、DuckDuckGo。
- 支持自定义搜索 URL 模板。
- 输入合法网址时可直接访问。
- 当前标签页或新标签页打开结果可配置。
- 支持清空、切换搜索引擎和键盘提交。
- 仅允许安全的搜索和导航协议。
- 联网搜索建议默认关闭，开启前说明关键词会发送给服务商。
- 本地快捷方式匹配可离线提供。
- 搜索建议属于弹层，不参与网格碰撞。
- 浏览器可能默认聚焦地址栏，因此不保证自动聚焦搜索框。

### 4.4 快捷方式图标（P0）

每个快捷方式是独立实例，字段至少包括名称、URL、图标、打开方式和实例 ID。

支持：

- 新建、编辑、删除、复制；
- 单独移动、插入和交换；
- 默认 1 × 1 网格尺寸；
- 自定义图标或首字母回退图标；
- 当前页或新标签页打开；
- URL 协议和格式校验；
- 图标缓存及失败回退；
- 可选锁定位置；
- 可选从书签导入，书签权限按需申请。

初始布局提供 20 个快捷图标位置。未配置的位置在普通模式下不显示厚重空卡片，在编辑模式下可显示轻量网格提示。20 个不是上限，新增图标可自动放置到后续网格。

### 4.5 推荐内置 Widget

首版至少实现一个纯本地 Widget 和一个联网 Widget，以验证完整运行机制。

| Widget | 功能 | 外部能力 | 建议阶段 |
|---|---|---|---|
| 待办事项 | 本地任务增删改和完成状态 | 无 | P0/P1 |
| 便签 | 本地文本记录 | 无 | P0/P1 |
| 天气 | 城市、温度和天气状态 | 白名单网络；定位可选 | P1 |
| 番茄钟 | 专注计时和状态 | 通知可选 | P1 |
| RSS 摘要 | 展示订阅内容 | 指定域名网络 | P1/P2 |

### 4.6 外观和全局设置（P0）

- 默认壁纸、自定义上传、渐变背景。
- 壁纸模糊、调暗和提亮遮罩。
- 浅色、深色、跟随系统。
- 材质质量：高、均衡、低、关闭。
- 动效与图标摆动开关。
- 网格编辑、智能整理、恢复默认。
- 撤销、重做。
- 数据导入、导出、清除。
- Widget 权限管理。
- 可选同步，不同步大型二进制资源。

## 5. iPad 主屏幕式统一网格

### 5.1 基本单位

标准宽屏采用 10 个图标列，以快捷图标为基本布局单位。所有坐标和尺寸使用整数，实际像素尺寸由容器宽度和响应式规则计算。

推荐尺寸：

| 对象 | 默认尺寸（网格单位） | 备注 |
|---|---|---|
| 快捷图标 | 1 × 1 | 图标和标签共同占据 |
| 搜索框 | 6 × 1 | 视觉内容可在占用区域内垂直居中 |
| 时钟 | 4 × 2 | 可声明其他预设 |
| 小型 Widget | 2 × 2 | 典型方形组件 |
| 中型 Widget | 4 × 2 | 典型横向组件 |
| 大型 Widget | 4 × 4 | 典型大组件 |

Widget 可以声明其他尺寸、最小尺寸、最大尺寸和尺寸预设，但不得小于内容可访问所需尺寸。

### 5.2 坐标与占用

每个布局对象至少记录：

- `instanceId`；
- `kind`：`shortcut` 或 `widget`；
- `x`、`y`、`w`、`h`；
- 是否锁定；
- 是否允许交换、推挤；
- 排序或分组元数据；
- 当前断点标识。

约束：

- `x >= 0`、`y >= 0`、`w >= 1`、`h >= 1`；
- `x + w <= 当前断点列数`；
- 任意两个不同对象的占用矩形不得同时具有横向和纵向交集；
- 边缘相接不算重叠；
- 页面高度可向下扩展；
- 普通网格对象没有 z 轴覆盖关系。

### 5.3 响应式断点

| 模式 | 列数 | 快捷图标表现 |
|---|---:|---|
| 宽屏 | 10 | 默认两行各 10 个 |
| 中等窗口 | 8 | 自动重排 |
| 窄窗口 | 5 | 自动重排并保留可操作性 |

每个断点保存独立布局。首次进入某断点时由参考布局生成；用户编辑后保存该断点版本。恢复宽屏时优先恢复宽屏布局，不用压缩后的坐标覆盖它。

具体像素断点在视觉原型阶段确定，列数变化必须依据可用容器宽度，而不是设备型号。

### 5.4 统一入口

以下操作必须经过同一个布局引擎：

- 新增加载项或 Widget；
- 移动和拖放；
- 尺寸调整；
- 交换；
- 自动推挤；
- 智能整理；
- 断点转换；
- 布局导入；
- 数据迁移；
- Widget 更新后尺寸约束变化。

任何 UI 代码不得直接写坐标后绕过全量校验。

### 5.5 新增对象放置

- 优先使用用户指定位置。
- 未指定时，从上到下、从左到右寻找首个完整空位。
- 若提供参考位置，则按距离和移动代价寻找最近空位。
- 空间不足时增加行。
- 不因自动放置而缩小对象。
- 自动放置结果同样可撤销。

## 6. 移动、交换、推挤与智能重排

本节能力全部为 P0，不再作为后续可选项。

### 6.1 自动模式决策

默认根据落点自动选择操作，并在提交前显示明确预览。

| 情况 | 默认行为 |
|---|---|
| 目标区域完全空闲 | 直接移动 |
| 落在一个同尺寸对象上 | 优先交换 |
| 不同尺寸对象可合法互换原区域 | 交换 |
| 不同尺寸直接交换会影响第三方对象 | 推挤或局部重排 |
| 落点覆盖多个对象 | 自动推挤 |
| 尺寸调整产生冲突 | 推挤受影响对象，必要时局部重排 |
| 当前断点没有布局 | 自适应重排 |
| 用户点击“智能整理” | 全局预览，确认后提交 |

设置提供三种偏好：自动判断、优先交换、优先推挤。无论偏好如何，都不能破坏不重叠约束。

### 6.2 拖放命中与预览

- 拖到图标主体区域：优先交换。
- 拖到图标之间或网格插入线：插入并推挤。
- 拖到空白格：移动。
- 拖到大型 Widget：依据覆盖矩形决定推挤或局部重排。
- 预览文字或图标应区分“移动”“交换”“推挤”“智能重排”和“无法放置”。
- 只有目标网格发生变化时才重新计算，不能随每个指针像素重复求解。
- 过期计算结果不得覆盖更新的拖动目标。

### 6.3 同尺寸交换

两个图标或两个相同尺寸 Widget 可直接交换坐标：

- 保留各自实例 ID、配置和数据；
- 不移动其他对象；
- 不自动修改尺寸；
- 整个交换记为一个撤销步骤。

### 6.4 不同尺寸交换

排除交换双方后，只有同时满足以下条件才可直接交换：

1. A 能完整放入 B 原区域；
2. B 能完整放入 A 原区域；
3. 双方均不与其他对象重叠或越界；
4. 不需要缩小任一对象；
5. 双方均未锁定。

不满足时进入推挤或局部重排。图标原位置放不下大型 Widget 时，不得把大型 Widget 缩成图标。

### 6.5 自动推挤

推挤用于为拖入对象腾出完整目标矩形：

- 图标插入当前行时，后续图标优先按阅读顺序移动；
- 当前行无空位时，链尾对象进入下一行；
- 大 Widget 放入图标群时，可移动多个图标；
- 页面末尾没有空位时自动增加行；
- 被推挤对象不能通过自动缩小来避让；
- 推挤结果保持最终无重叠。

### 6.6 推挤方向与候选顺序

默认候选顺序：

1. 与拖动方向一致的最近位置；
2. 当前行阅读顺序的后续位置；
3. 下方最近位置；
4. 其他方向最近位置；
5. 新增行。

图标优先保持相对顺序；Widget 优先最小化移动距离。候选评分相同时使用固定阅读顺序和实例 ID 作为确定性决胜条件。

### 6.7 链式推挤

链式推挤可能形成“A 移到 B，B 移到 C，C 移到空位”。实现要求：

- 在布局副本上计算完整链条；
- 保存已访问对象和布局状态签名；
- 检测循环并尝试其他候选；
- 限制单次求解的对象数、搜索节点和执行时间；
- 超限时使用局部重排或安全回滚；
- 先求出合法结果，再播放位移动画；
- 整条链一次提交、一次撤销。

### 6.8 锁定对象

- 锁定对象不参与自动推挤、交换和全局整理。
- 求解器必须绕开锁定对象。
- 用户手动移动锁定对象时先提示解锁。
- 找不到合法布局时保持原布局并说明原因。
- 断点自适应也尽量保持锁定对象的相对区域；尺寸无法兼容时标记冲突并请求处理，不静默覆盖。

### 6.9 局部智能重排

局部重排是自动推挤无法低成本解决时的补救机制：

1. 固定拖动对象及目标位置。
2. 固定所有锁定对象。
3. 找出直接冲突对象。
4. 扩展到间接受影响对象，形成局部问题集。
5. 优先生成附近候选位置。
6. 必要时扩大区域或增加行。
7. 对每个候选执行边界和全量碰撞检查。
8. 选择评分最高的合法结果。
9. 一次提交并允许整体撤销。

普通拖动不得无提示地整理整个页面。

### 6.10 布局评分顺序

1. 合法：不重叠、不越界、符合尺寸约束。
2. 不移动锁定对象。
3. 不改变对象尺寸。
4. 移动对象数量最少。
5. 总网格移动距离最小。
6. 保持图标相对顺序。
7. 保持用户分组的邻近关系。
8. 减少无意义的大块空洞。
9. 尽量不增加页面高度。
10. 新空位优先位于阅读顺序末尾。

“智能”指确定性的约束求解与启发式评分，不要求接入 AI 服务。

### 6.11 全局智能整理

提供两种模式：

**保持分组**

- 保留明显的组件组和用户空白；
- 只整理局部空洞；
- 尽量不跨组移动；
- 保持原视觉结构。

**紧凑排列**

- 按阅读顺序向上、向左压缩；
- 优先减少空白行；
- 保持图标相对顺序；
- 先定位大型 Widget，再使用图标和小组件填充空位。

全局整理必须提供预览、影响对象数量、页面高度变化、确认和取消。整理后仍只记一个撤销事务。

> **2026-11-17 变更（用户指示）**：紧凑排列改为**点击即整理并保存**，不再要求确认步骤；「影响对象数量 / 页面高度变化」也随之不再展示。整理仍然只记一个撤销事务，一次撤销即可完整回退。拖动产生的临时布局预览与 `Esc` 取消不受影响。详见 `docs/implementation-plan.md` 的对应实现记录。

### 6.12 断点自适应重排

- 保持对象相对顺序和分组邻近关系。
- 过宽 Widget 优先换行，不缩至最小尺寸以下。
- 大对象先放置，小对象填充剩余空间。
- 无法保留原分组时，优先保证合法性和可操作性。
- 结果仅保存到当前断点。
- 已存在当前断点布局时优先恢复，不重复自动整理。

### 6.13 布局事务

所有布局变更遵循同一事务流程：

1. 捕获操作前快照和修订号；
2. 在副本上计算；
3. 执行尺寸、边界、碰撞和锁定校验；
4. 生成预览；
5. 松手或确认后提交；
6. 持久化并广播新修订；
7. 记录一个撤销步骤。

失败、取消或超时必须恢复操作前状态，不能留下半完成布局。撤销恢复整个事务，重做重新应用整个事务。

## 7. 编辑交互、状态与可访问性

### 7.1 普通模式

- 单击快捷图标：打开网页。
- 鼠标移动超过约 6～8px 后：识别为拖动而非点击。
- Widget 内部按钮、输入框和滚动区域保留自身交互。
- 拖动 Widget 标题区、空白区或专用手柄：移动 Widget。
- 右键或长按：打开上下文菜单。
- 普通模式不持续显示密集网格线。

### 7.2 编辑模式

通过“编辑主屏幕”或长按空白区域进入：

- 显示轻量网格、空位和拖拽手柄；
- 显示图标删除入口；
- 显示 Widget 尺寸手柄和尺寸预设；
- 提供锁定、设置、复制和移除；
- 可使用轻微图标摆动，减少动态效果时禁用；
- 点击“完成”或按 `Esc` 退出；
- 未提交拖动按 `Esc` 先取消本次事务。

### 7.3 键盘操作

P0 至少支持：

- `Tab` 在交互元素间移动；
- `Enter` 打开图标或确认当前布局操作；
- `Esc` 取消；
- `Ctrl/Cmd + Z` 撤销；
- `Ctrl/Cmd + Shift + Z` 重做；
- 编辑模式中选中对象后用方向键移动；
- 提供键盘调整尺寸的明确方式；
- 所有快捷键不得覆盖输入框中的正常文本编辑。

### 7.4 焦点与语义

- 图标使用可理解的名称和链接语义。
- Widget 容器具有名称、角色和状态说明。
- 拖放不是完成布局的唯一方式。
- 焦点顺序与视觉阅读顺序基本一致。
- 重排后焦点保持在原操作对象上。
- 错误、权限拒绝和布局失败以文字说明，不能只靠颜色。
- 沙箱 Widget 的无障碍边界和标题需要明确标注。

### 7.5 动画

- 被推挤对象可在拖动预览中提前让位。
- 交换双方平滑移动。
- 智能重排仅动画实际变化的对象。
- 普通过渡建议 160～240ms，最终以原型测试为准。
- 预览不持久化，提交后一次保存。
- 减少动态效果时使用即时切换或简单淡入淡出。
- 页面不可见时停止装饰动画。

## 8. Apple 风格与 Liquid Glass 视觉规范

### 8.1 官方原则的落地

Apple 官方资料将 Liquid Glass 定位为悬浮于内容上方的控件和导航功能层，并强调避免在内容层滥用、避免玻璃叠放、保证可读性、使用同心圆角以及适配辅助功能。因此本项目不将每个卡片和按钮都做成独立玻璃层。

### 8.2 材质分配

| 元素 | 推荐视觉 |
|---|---|
| 时钟、日期 | 透明文字、轻阴影、背景自适应 |
| 快捷图标 | 清晰图标和标签，不为每个标签叠加玻璃卡 |
| 搜索框 | 单层常规 Liquid Glass |
| 编辑、添加、设置按钮 | Liquid Glass 功能控件 |
| 日历、待办、天气等内容 Widget | 标准半透明材质或轻量实体表面 |
| 菜单和设置弹层 | 单层玻璃，内部控件使用普通填充 |
| 拖动预览 | 临时功能层高亮，避免多层玻璃叠加 |

默认使用“常规”视觉变体。高度透明的 Clear 风格只在富媒体背景、具有调暗层且前景明亮时提供，不与常规变体混用。

### 8.3 macOS 原生能力边界

普通 Chrome、Edge、Firefox 或 Safari Web Extension 的新标签页均由 Web 技术渲染。Safari 的原生容器 App 可以提供原生设置界面、共享代码或原生消息能力，但不会把新标签页 DOM 自动变成 AppKit/SwiftUI 控件。

因此：

- **P0/P1 采用跨浏览器 Web 模拟。**
- macOS 做 Safari/WebKit 和 Chromium 的专项视觉优化。
- 完全原生 Liquid Glass 需要独立 macOS App 或原生窗口方案，应另行立项，不能作为浏览器扩展的默认承诺。

### 8.4 Web 模拟层

建议将材质拆为可独立降级的视觉层：

1. 背景模糊；
2. 适度饱和度调整；
3. 半透明着色；
4. 边缘高光和内描边；
5. 柔和外阴影；
6. 随背景明暗变化的遮罩；
7. 交互高光；
8. 高质量模式下的局部折射近似。

实现可使用 CSS 背景、`backdrop-filter`、伪元素和渐变；高开销 SVG 滤镜只能作为可选增强。不能宣称与 macOS 原生材质逐像素一致。

### 8.5 设计变量初值

以下为项目初值，不是 Apple 官方固定数值：

| 项目 | 建议 |
|---|---|
| 字体 | macOS 系统字体，其他平台使用系统回退 |
| 时钟 | 响应式约 88～144px，等宽数字 |
| 日期 | 约 18～24px |
| 搜索文字 | 约 16px |
| Widget 正文 | 约 14px |
| Widget 标题 | 约 15～17px |
| 间距基础 | 4/8 倍数体系 |
| 页面最大内容宽度 | 约 1440～1600px，原型校准 |
| 普通过渡 | 约 160～240ms |

不打包 Apple 专有字体或壁纸。默认图标和背景使用自制或许可明确的资源。

### 8.6 圆角、颜色和对比度

- 嵌套圆角遵循同心关系：内圆角约等于外圆角减去内边距。
- 搜索框可使用胶囊形；桌面高密度小控件不强制全部胶囊化。
- 强调色只用于主要操作、选中态和状态提示。
- 支持浅色、深色和跟随系统。
- 壁纸复杂时增加调暗或提亮层，不能只靠文字阴影维持可读性。
- 普通文字对比度目标至少 4.5:1，大号文字至少 3:1，关键控件边界至少 3:1。
- 提供高对比度和强制颜色模式的可用回退。

### 8.7 材质质量等级

| 等级 | 表现 |
|---|---|
| 高 | 完整模糊、高光、阴影和可选局部折射 |
| 均衡 | 保留模糊与高光，减少动态光效和折射 |
| 低 | 静态半透明背景、普通边框和阴影 |
| 关闭 | 高对比度实体表面 |

“降低透明度”“提高对比度”“减少动态效果”等系统偏好，在浏览器可检测时自动响应，同时提供扩展内独立设置。

## 9. 总体技术架构

### 9.1 推荐技术方向

技术选型建议为 TypeScript、组件化 Web UI、CSS 设计变量和按浏览器目标构建的 Manifest V3 包。UI 框架可在原型阶段选择 React 或 Preact，不能把布局引擎与框架生命周期耦合。

核心原则：

- 布局引擎使用独立、可测试的纯逻辑模块；
- Widget 消息协议独立于 UI 框架；
- 核心资源本地打包，不依赖运行时 CDN；
- 浏览器差异集中在适配层；
- 不通过远程主页 URL 实现新标签页；
- 依赖版本在开发启动时锁定，本文不预设具体版本号。

### 9.2 逻辑模块

| 模块 | 职责 |
|---|---|
| New Tab App | 主屏幕、设置、组件画廊和编辑模式 |
| Grid Engine | 坐标、占用、碰撞、交换、推挤、重排和事务 |
| State Store | 页面状态、选择态、撤销重做和订阅 |
| Persistence | 本地存储、修订、迁移、导入导出 |
| Theme Engine | 设计变量、明暗、材质质量和背景遮罩 |
| Widget Host | 生命周期、沙箱、消息路由、错误隔离 |
| Permission Broker | 网络、通知、书签、定位等权限代理 |
| Background Worker | 受限刷新、后台任务和跨页面协调 |
| Browser Adapter | 各浏览器 API 和清单差异 |
| Diagnostics | 受限日志、错误状态和数据清理 |

### 9.3 布局引擎输入与输出

输入至少包括：

- 当前断点列数；
- 当前布局及修订号；
- 对象尺寸和约束；
- 锁定、交换和推挤配置；
- 操作类型与目标矩形；
- 用户偏好。

输出至少包括：

- 成功或失败状态；
- 候选完整布局；
- 变化对象及原、新坐标；
- 操作类型；
- 失败原因；
- 页面高度变化；
- 可用于撤销的事务记录。

提交前必须对候选完整布局再次验证，不能只检查被拖动对象。

### 9.4 运行流程

1. 浏览器加载本地新标签页。
2. 读取并迁移设置、布局和实例数据。
3. 先渲染本地时钟、搜索和图标骨架。
4. 初始化主题和壁纸。
5. 挂载 Widget Host 并恢复可见实例。
6. 后台检查过期数据，不阻塞首屏。
7. 用户操作进入布局事务或 Widget 消息流程。
8. 页面隐藏时暂停非必要刷新。

### 9.5 多页面与后台限制

多个新标签页可能同时存在：

- 非编辑页面接收最新修订并更新；
- 编辑中的页面不被外部更新强行打断；
- 提交时检查修订号；
- 修订冲突时重新计算或提示，不静默覆盖；
- 后台 Service Worker 可能被休眠，Widget 不得假设永久运行。

## 10. 可编程 Widget SDK

### 10.1 目标与信任分级

Widget 系统需要同时支持内置组件和后续第三方组件，但两者权限边界不同：

- **内置 Widget**：随扩展审核和发布，可使用内部优化接口，仍应尽量通过统一能力层访问敏感资源。
- **第三方 Widget**：默认不可信，必须沙箱运行，只通过版本化消息协议使用显式授权能力。
- **开发模式 Widget**：本地导入用于开发测试，必须显示明显风险提示，不默认继承额外权限。

任何 Widget 都不能直接修改网格坐标。尺寸变化请求必须交给布局引擎处理。

### 10.2 组件包结构

一个 Widget 包逻辑上包括：

- 组件清单；
- 本地入口 HTML；
- 本地 JavaScript 和 CSS；
- 图标及静态资源；
- 设置结构定义；
- 多语言资源；
- 权限声明；
- 版本和宿主兼容范围；
- 可选数据迁移说明。

运行时禁止从未知远程地址下载并执行脚本。公开分发时还需增加签名、作者身份和审核信息。

### 10.3 清单字段

| 字段 | 必需性 | 说明 |
|---|---|---|
| `id` | 必需 | 全局唯一 ID，推荐反向域名格式 |
| `version` | 必需 | 组件包版本，采用语义化版本 |
| `apiVersion` | 必需 | 使用的 Widget SDK 主版本 |
| `name`、`description` | 必需 | 展示信息 |
| `entry` | 必需 | 包内本地入口 |
| `icon` | 必需 | 包内图标资源 |
| `defaultSize` | 必需 | 默认网格尺寸 |
| `sizes` | 必需 | 尺寸预设、最小和最大约束 |
| `settingsSchema` | 可选 | 设置字段、默认值和校验规则 |
| `permissions` | 可选 | 能力和网络域名，默认空 |
| `refreshPolicy` | 可选 | 可见刷新和后台刷新需求 |
| `minHostVersion` | 必需 | 最低宿主版本 |
| `locales` | 可选 | 支持语言及资源 |
| `author`、`homepage` | 推荐 | 作者和支持入口 |

安装时校验路径遍历、重复 ID、非法资源类型、未知权限、不兼容 API 和尺寸约束。

### 10.4 沙箱运行

第三方 Widget 推荐运行于沙箱化 iframe：

- 不直接访问父页面 DOM；
- 不直接访问其他 Widget；
- 不直接调用扩展 API；
- 不直接读写宿主存储；
- 默认不能顶层导航、打开弹窗或访问剪贴板；
- 使用独立 CSP，禁止 `eval` 和等效动态执行；
- CSS 不能污染宿主；
- 设置页与主体采用相同隔离原则；
- 父页面只暴露受控主题变量和尺寸信息。

宿主必须验证消息来源、目标实例和会话，不能只依据 Widget 自报的 ID 授权。

### 10.5 消息协议

消息采用异步请求、响应和事件模型。逻辑字段至少包括：

| 字段 | 用途 |
|---|---|
| `protocolVersion` | 协议兼容判断 |
| `messageId` | 请求与响应关联、去重 |
| `instanceId` | 目标实例，仍需与消息来源交叉验证 |
| `type` | 请求、响应、事件或错误 |
| `method` | 能力名称 |
| `payload` | 经结构校验的参数 |
| `timestamp` | 诊断和过期判断 |
| `error` | 稳定错误码和可展示信息 |

要求：

- 为每类消息定义参数和返回值结构；
- 设置超时、数据大小和调用频率限制；
- 对重复请求进行去重或明确幂等性；
- Widget 卸载后拒绝其后续请求；
- 协议错误不得导致主页面异常；
- 不在日志中记录令牌、搜索内容或私人数据。

### 10.6 SDK 能力分类

| 能力 | 内容 | 默认授权 |
|---|---|---|
| 环境信息 | 主题、语言、尺寸、减少动态效果、材质质量 | 只读开放 |
| 生命周期 | 挂载、卸载、显示、隐藏、尺寸变化 | 开放 |
| 实例配置 | 读取设置、响应设置变化 | 本实例开放 |
| 实例存储 | 保存本实例用户数据和缓存 | 开放但有配额 |
| 网络请求 | 通过宿主访问白名单域名 | 按域名授权 |
| 定时刷新 | 请求宿主安排刷新 | 受调度限制 |
| 打开链接 | 用户操作后打开安全 URL | 需用户手势 |
| 通知 | 创建浏览器通知 | 可选权限 |
| 书签读取 | 导入或展示书签 | 可选权限 |
| 定位 | 获取位置 | 可选权限 |
| 日志 | 提交受限诊断信息 | 开放但脱敏 |

Widget 之间默认不能直接调用。后续组件联动必须增加用户可见的事件订阅和授权机制。

### 10.7 生命周期事件

宿主至少提供以下概念事件：

- 安装、启用、禁用；
- 创建实例、挂载、卸载；
- 可见、隐藏；
- 尺寸变化；
- 设置变化；
- 主题、语言和辅助功能变化；
- 手动刷新和计划刷新；
- 权限变化；
- 组件更新和数据迁移；
- 实例删除和组件卸载。

页面隐藏不代表数据被删除；后台线程休眠也不保证收到完整计时事件。Widget 必须能从持久化状态恢复。

### 10.8 网络代理

第三方 Widget 的网络请求默认经过 Permission Broker：

- 仅允许清单声明且用户授权的域名；
- 仅允许 HTTP/HTTPS，按能力限制方法；
- 默认不携带 Cookie、登录凭据或敏感浏览器请求头；
- 限制重定向、响应大小、超时和并发；
- 防止通过重定向绕过域名白名单；
- 缓存按实例和域名隔离；
- 外部 HTML 默认按文本处理，确需渲染时必须清理；
- 外部链接限制协议并防止来源窗口被反向控制。

Widget 清单不能突破宿主扩展可声明权限的上限。宿主未声明或无法动态申请的权限，不能通过 Widget 清单凭空获得。

### 10.9 刷新与后台任务

- 页面可见时按数据过期时间刷新；
- 多个 Widget 的网络任务可合并调度；
- 后台刷新使用浏览器允许的 alarms 或等效机制；
- 不承诺精确分钟或秒级后台执行；
- 限制频率、失败重试和指数退避；
- 页面重新可见时校准状态；
- 无网络时显示缓存和过期状态，不无限加载。

### 10.10 错误隔离

以下情况显示独立错误卡片：

- 加载或响应超时；
- 脚本异常；
- 协议不兼容；
- 权限被拒绝；
- 网络失败；
- 返回数据不合法；
- 存储配额不足。

错误卡片保留原网格位置，提供重试、重新授权、禁用和移除。Widget 故障不能影响时钟、搜索、图标和布局引擎。

### 10.11 版本与更新

分别管理宿主版本、SDK 协议版本和 Widget 包版本：

- 主版本不兼容时拒绝加载并保留用户数据；
- 兼容更新按声明执行数据迁移；
- 更新前备份实例数据；
- 迁移失败时禁用更新实例并允许回滚或恢复；
- 不静默删除旧版本数据；
- 布局尺寸约束变化必须经过布局引擎重新放置。

### 10.12 开发者工具

后续 SDK 交付物包括：

- Widget 包校验器；
- 本地开发模板；
- 模拟宿主和消息测试工具；
- 设置界面生成器；
- 主题变量和尺寸规范；
- 纯本地与联网示例 Widget；
- 权限测试、迁移测试和错误注入工具；
- 调试日志查看器。

P0 先稳定内部协议；P1 开放开发模式；公开签名分发和市场列入 P2。

## 11. 数据模型、存储与迁移

以下为逻辑模型，字段可在技术设计阶段细化，但核心约束不能省略。

### 11.1 Workspace

表示一套用户主屏幕配置：

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 数据结构版本 |
| `workspaceId` | 工作区 ID |
| `revision` | 并发和冲突检测 |
| `createdAt`、`updatedAt` | 时间信息 |
| `settings` | 外观、搜索、网格等设置 |
| `layouts` | 各断点布局 |
| `shortcuts` | 快捷方式实例 |
| `widgets` | Widget 实例 |
| `installedWidgets` | 已安装组件及版本信息 |

### 11.2 LayoutItem

| 字段 | 说明 |
|---|---|
| `instanceId` | 与快捷方式或 Widget 实例对应 |
| `breakpoint` | 宽屏、中等、窄屏等布局标识 |
| `x`、`y`、`w`、`h` | 整数网格矩形 |
| `locked` | 是否禁止自动移动 |
| `groupId` | 可选用户分组 |
| `order` | 同阅读顺序下的稳定排序辅助 |
| `updatedAt` | 冲突处理辅助 |

布局项只描述几何和布局元数据，不重复保存 Widget 内部用户数据。

### 11.3 Shortcut

| 字段 | 说明 |
|---|---|
| `id` | 独立实例 ID |
| `title` | 展示名称 |
| `url` | 经校验的目标地址 |
| `icon` | 本地资源、缓存引用或回退策略 |
| `openTarget` | 当前页或新标签页 |
| `accentColor` | 可选强调色 |
| `createdAt`、`updatedAt` | 同步和排序辅助 |

### 11.4 WidgetInstance

| 字段 | 说明 |
|---|---|
| `instanceId` | 实例 ID |
| `widgetId` | 组件包 ID |
| `widgetVersion` | 创建或最近迁移时的版本 |
| `enabled` | 是否启用 |
| `settings` | 本实例配置 |
| `grantedPermissions` | 实际授权记录 |
| `storageNamespace` | 独立存储命名空间 |
| `lastRefreshAt` | 数据刷新状态 |
| `errorState` | 可恢复错误信息 |

同一 Widget 可创建多个实例，设置、权限使用情况和数据必须相互隔离。

### 11.5 Settings

至少包括：

- 主题、壁纸、遮罩和材质质量；
- 动效、减少动态效果和高对比度偏好；
- 搜索引擎、打开方式和搜索建议开关；
- 时间格式、时区和每周第一天；
- 拖放偏好：自动、优先交换、优先推挤；
- 智能整理偏好；
- 数据同步和隐私选项。

### 11.6 存储映射

| 数据 | 推荐存储 |
|---|---|
| 设置、布局、快捷方式、实例元数据 | 扩展结构化本地存储 |
| 待办、便签等 Widget 数据 | 按实例隔离的本地存储 |
| 壁纸、大型图标和二进制资源 | IndexedDB 或等效本地二进制存储 |
| 网络缓存和图标缓存 | 可清理本地缓存 |
| 小型同步设置 | 可选浏览器同步存储 |

浏览器同步配额需要在实现时实测，大型图片和缓存默认不同步。

### 11.7 修订与并发

- Workspace 和布局提交携带修订号。
- 非编辑页面接受新修订并更新。
- 编辑页面提交前比较修订号。
- 冲突时优先基于最新布局重新执行事务；无法安全重放则提示用户。
- 不以“最后写入”为由静默覆盖一整页复杂布局。
- 存储失败时不展示“已保存”的成功状态。

### 11.8 导入与导出

导出内容：

- 设置；
- 各断点布局；
- 快捷方式；
- Widget 实例配置和用户数据；
- 资源引用及必要资源；
- 数据版本和导出时间。

默认不在备份中包含第三方可执行 Widget 包。导入前校验版本、结构、实例引用、网格约束和危险 URL；无效数据不得部分覆盖现有工作区。大型导入先解析和预览，再一次提交。

### 11.9 数据迁移

- 每个持久化结构具有 `schemaVersion`。
- 迁移按版本顺序执行并保证可重复验证。
- 迁移前保留备份。
- 迁移后进行引用完整性和布局合法性检查。
- 失败时停止启动写入并进入恢复界面。
- 新版不随意删除无法识别的数据字段。

## 12. 权限、安全与隐私

### 12.1 最小权限原则

P0 只申请新标签页和本地运行所需权限。书签、常用网站、定位、通知和广泛网络访问按需申请，不为了未来功能一次性索取全部权限。

### 12.2 内容安全

- 核心页面和 Widget 使用严格 CSP。
- 不执行远程脚本，不使用 `eval`。
- 限制 `javascript:` 等危险 URL。
- 自定义搜索模板和外部导航统一校验。
- 用户文本和 Widget 数据默认按文本渲染。
- 第三方 HTML 必须清理或使用安全展示方式。
- 图标和图片上传限制格式、尺寸和解码资源消耗。
- Widget 包解包前检查路径和大小，防止路径遍历与压缩炸弹。
- 外部页面与扩展之间不建立未授权消息通道。

### 12.3 权限展示

安装或启用 Widget 前显示：

- 所需能力；
- 具体网络域名；
- 数据用途；
- 是否后台运行；
- 拒绝后的功能影响。

用户可撤销权限。撤销后 Widget 进入降级或错误状态，不能继续利用缓存凭据访问敏感资源。

### 12.4 隐私默认值

- 不默认读取浏览历史、书签和常用网站。
- 不默认开启搜索建议。
- 不默认开启定位。
- 不内置广告或行为统计。
- 天气优先手动城市。
- 第三方图标服务和天气请求明确披露。
- 提供清除缓存、清除单 Widget 数据和清除全部数据入口。
- 核心功能离线可用，账号不是前提。

## 13. 性能、可靠性与兼容性

### 13.1 性能预算

以下为开发目标，需要在目标设备实测校准：

| 指标 | 目标 |
|---|---|
| 本地基础首屏 | 正常缓存条件下约 500ms 内出现 |
| 主要交互可用 | 目标约 1 秒内 |
| 拖动与推挤动画 | 尽量接近 60fps，无明显长任务卡顿 |
| 无操作状态 | 不运行持续装饰动画 |
| 存储写入 | 拖动结束时提交，不随指针移动写入 |
| Widget 加载 | 不阻塞时钟、搜索和快捷图标 |

不能通过降低布局正确性换取动画流畅度。复杂求解应有节点或时间预算，并支持取消过期任务。

### 13.2 渲染与计算要求

- 指针移动只更新轻量预览，目标格变化才重新求解。
- 避免在动画中反复读取和写入布局造成强制同步回流。
- 大壁纸延迟解码并限制尺寸。
- 减少同时存在的全屏模糊层。
- 不可见 Widget 暂停非必要任务。
- 时钟按显示精度更新。
- 对快速连续拖动使用操作序号或取消机制，旧结果不能覆盖新状态。

### 13.3 可靠性

- 所有布局事务可回滚。
- 所有持久化数据带版本。
- 单个 Widget 异常不扩散。
- 存储失败、权限拒绝和离线状态具有明确 UI。
- 多标签页修订冲突可检测。
- 损坏的布局在加载时修复到合法状态，并保留恢复信息。
- 自动修复不得无提示删除用户对象。

### 13.4 浏览器兼容矩阵

开发阶段需逐项记录 Chrome、Edge、Firefox、Safari 的实际支持和最低版本：

- 新标签页覆盖；
- Manifest V3 与后台线程；
- 可选权限；
- storage 与 IndexedDB；
- 多标签页消息；
- 沙箱页面和 CSP；
- `backdrop-filter`；
- 系统明暗和辅助功能媒体查询；
- 通知、书签和定位；
- 导入导出与文件处理；
- 浏览器同步。

不支持的能力采用功能降级，不通过不可靠私有 API 强行实现。

## 14. 测试与验收标准

### 14.1 测试层级

| 层级 | 重点 |
|---|---|
| 单元测试 | 坐标、矩形碰撞、候选位置、排序、迁移和 URL 校验 |
| 属性测试 | 随机布局经过操作后仍不重叠、不越界，实例不丢失 |
| 事务测试 | 交换、推挤、重排、撤销、重做、取消和冲突回滚 |
| 集成测试 | 存储、多标签页修订、Widget 消息和权限代理 |
| 端到端测试 | 新标签页、搜索、图标、拖动、设置和导入导出 |
| 安全测试 | 沙箱逃逸尝试、伪造消息、危险 URL、权限绕过和恶意包 |
| 视觉测试 | 明暗主题、不同壁纸、断点、材质降级和焦点状态 |
| 性能测试 | 首屏、长任务、连续拖动、大布局和高开销材质 |
| 人工探索 | 操作可预测性、iPad 式手感、误拖和动画舒适度 |

### 14.2 布局引擎必测用例

1. 空位移动只改变目标对象。
2. 图标插入两个图标之间产生正确的链式推挤。
3. 当前行满时链尾进入下一行。
4. 页面末尾无空位时自动增加行。
5. 同尺寸图标和 Widget 正确交换。
6. 不同尺寸仅在合法时直接交换。
7. 不同尺寸无法直接交换时进入推挤或局部重排。
8. 大 Widget 放入图标密集区后无重叠。
9. 推挤链出现循环时能检测并选择其他路径或回滚。
10. 锁定对象不被自动操作移动。
11. 所有对象保持原实例 ID、配置和用户数据。
12. 推挤或重排不会自动缩小对象。
13. 撤销一次恢复整条链，重做恢复整个结果。
14. `Esc` 取消所有预览位移。
15. 快速连续拖动时旧计算不能覆盖新目标。
16. 求解超时或存储失败时完整回滚。
17. 10 列转 8 列、5 列后无重叠。
18. 恢复原断点后恢复用户此前布局。
19. 全局整理在确认前不修改持久化数据。
20. 随机合法布局执行操作后，对象数量不无故减少且没有重复实例。

建议增加不变量检查：每次布局提交后，所有实例必须恰好出现一次，坐标为整数、尺寸合法、边界合法且两两不重叠。

### 14.3 核心功能验收

| 场景 | 通过条件 |
|---|---|
| 首次安装 | 显示时钟、日历、搜索、默认快捷图标和 Widget 入口 |
| 默认图标布局 | 宽屏初始为两行各 10 个，每个可独立操作 |
| 搜索 | 搜索引擎切换、提交、网址识别和打开方式正确 |
| 快捷图标 | 增删改、拖动、交换和图标回退正常 |
| 时钟日历 | 时间格式、时区、月历切换和尺寸模式正确 |
| 布局持久化 | 浏览器重启后各断点布局保持 |
| 多标签页 | 修订同步可检测，不静默覆盖编辑冲突 |
| 智能整理 | 点击即整理并保存，一次提交并可一步撤销（2026-11-17 起不再要求确认，见 6.11 注） |
| 数据备份 | 导出再导入可恢复设置、布局、图标和 Widget 数据 |
| 离线 | 核心时钟、搜索入口、图标和本地 Widget 可用 |
| 减少动态效果 | 所有核心操作可用，非必要动画关闭 |
| 材质关闭 | 回退表面清晰，无文字不可读问题 |

### 14.4 Widget 与安全验收

- 同一 Widget 多实例的数据和设置互不影响。
- 未授权 Widget 无法访问网络、书签、定位或通知。
- 伪造实例 ID 或消息来源不能调用其他实例能力。
- Widget 无法读取父页面 DOM 和其他实例存储。
- Widget 超时、异常和非法数据仅影响自身错误卡片。
- 网络重定向不能绕过域名白名单。
- 危险 URL、远程脚本和动态执行被拒绝。
- 恶意压缩包、路径遍历和超大资源被拒绝。
- API 主版本不兼容时保留数据并显示明确提示。
- 权限撤销后相关能力立即停止，已有界面进入合理降级状态。

### 14.5 视觉、无障碍和性能验收

- 浅色、深色、复杂明暗壁纸下均满足约定对比度。
- 键盘可以完成核心导航和布局操作。
- 焦点在重排后不会无故丢失。
- 屏幕阅读器能理解图标、Widget 和操作状态。
- 宽屏、中等、窄屏均无意外横向溢出。
- 高、均衡、低和关闭材质等级均有实际差异。
- 连续拖动没有明显布局抖动和过期动画。
- Widget 网络加载不阻塞基础首屏。
- 性能结果记录设备、浏览器、窗口、对象数量和质量等级，不能只给主观结论。

### 14.6 发布门槛

发布前必须满足：

- P0 验收用例全部通过；
- 布局不变量测试无失败；
- 无未处理的高风险安全问题；
- 数据迁移和恢复路径已验证；
- 至少完成首发 Chrome、Edge 的真实浏览器测试；
- 已知浏览器差异和降级行为写入发布说明；
- 不以单元测试通过代替真实浏览器验收。

| 多选拖动 | P2 | 批量移动、推挤和撤销 |
| 浏览器同步 | P1 | 仅同步适合的数据，处理冲突和配额 |
| 书签导入 | P1 | 用户主动触发并申请权限 |
| 日历事件 | P2 | 按平台评估系统或在线日历 |
| Widget 签名分发 | P2 | 公开生态前必须完成安全机制 |
| 原生 macOS 容器 | 另行立项 | 不等同于普通浏览器扩展 |

### 16.2 当前默认决策

除非后续修改，开发按以下默认值推进：

1. Chrome、Edge 首发，Safari 和 Firefox 后续适配。
2. 新标签页为主，启动页和主页按钮按浏览器能力支持。
3. 日历支持日期摘要和完整月历两种模式。
4. P0 使用单页连续向下扩展网格；横向多页、Dock 和文件夹不在 P0。
5. 普通拖动只局部重排，全局整理必须预览确认。
6. 第三方 Widget 在 P1 以开发模式开放，P0 先稳定内部接口。
7. 核心功能完全离线；天气、搜索建议和在线图标按需联网。
8. 使用跨浏览器 Web 材质模拟，macOS 原生版本不阻塞扩展开发。

### 16.3 修改设计时的约束

- 若加入分页，需扩展 Workspace、LayoutItem、拖动状态和跨页事务。
- 若加入 Dock，不得让 Dock 与普通网格共享同一坐标却使用不同碰撞规则。
- 若加入文件夹，文件夹本身作为网格实例，内部图标不直接出现在主屏幕占用矩阵。
- 若允许任意尺寸自由缩放，必须重新评估图标对齐和智能重排评分。
- 若开放第三方远程代码，必须重新进行扩展商店政策、安全和签名设计，不能直接放开 CSP。
