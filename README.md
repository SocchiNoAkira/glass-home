# Glass Home

本地优先的 Liquid Glass 风格浏览器新标签页。

**当前状态：阶段 0、1、2A 已验收；阶段 2B-1、2B-2、3、4 已实现并通过自测，等待用户检查。**
不是正式发布版本。基线 14.6 要求 Chrome 与 Edge 双真机验收，本机未安装 Chrome，**仅 Edge 已实测**。

## 本地开发

项目目录：`/Volumes/Cupcake/Workspace/glass-home`。要求：macOS / Node.js 22 或更新 / pnpm。

```bash
pnpm install
pnpm dev
pnpm build
```

生产扩展输出：`/Volumes/Cupcake/Workspace/glass-home/.output/chrome-mv3`。在 Edge 打开 `edge://extensions`，启用开发者模式，选择“加载解压缩的扩展”，加载上述目录。

当前已通过 TypeScript、**200 项单元/属性测试**（另有 2 项显式跳过并注明浏览器覆盖位置）、生产构建，以及 **41 个真实 Edge 用例连续两轮共 82 次执行**。全部阶段的实施记录、验证结果与未完成清单统一维护在 `docs/implementation-plan.md`。

## 检查

```bash
pnpm check
pnpm build
pnpm test:e2e
```

`pnpm check` 依次运行类型检查、单元测试和生产构建。E2E 调用本机 Microsoft Edge 加载生产扩展，因此先执行 `pnpm build`。测试使用独立临时浏览器 profile，结束后清理；截图与报告保存在 `artifacts/`（已忽略 Git）。

默认 E2E 运行 `tests/e2e/stage-[1-4]*.spec.ts`，即阶段 1、2A、2B-1/2B-2、3、4 的全部用例（41 个）。旧原型用例归档为 `stage-0.spec.ts.archived`，不纳入默认回归，避免继续断言已移除的设计面板。

等分调试时可只跑某个阶段：

```bash
pnpm exec playwright test tests/e2e/stage-4-data.spec.ts      # 只看阶段 4
pnpm exec playwright test --repeat-each=2                     # 全量两轮（发布前门槛）
pnpm exec playwright test --headed --workers=1 -g "清除"      # 按用例名筛选，可见窗口
```

## 当前能力

- 本地 MV3 新标签页，离线打开时钟、日期、月历、搜索和快捷图标。
- 搜索与直接网址导航；自定义搜索模板及危险协议本地拒绝。搜索只在你主动提交时访问所选服务，没有联网搜索建议。
- 20 个默认快捷图标，支持新增、编辑、复制、删除、文字/颜色回退；新增项在三个断点分别寻找合法空位。
- 时钟、搜索、日历和快捷图标共享 v1 整数网格数据模型；10/8/5 列独立布局。
- 编辑态目标格面板支持移动、交换、强制推挤、尺寸预设、锁定、预览、取消和撤销/重做。保存只影响目标断点；写入失败恢复旧布局。
- 指针拖放：普通模式与编辑模式均可拖动图标与 Widget。移动超过 6px 才算拖动，松手才提交；拖到图标本体为交换，拖到图标之间为插入推挤，拖到空白格为移动。拖动中显示源位轮廓与目标格反馈，`Esc` 或指针取消即回滚且不写入本地。
- 键盘布局：编辑模式下 `Tab` 选中对象后，方向键移动一格、`Alt+方向键` 调整尺寸；重排后焦点留在原对象。`Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 重做，输入框内的撤销不受影响。
- 普通点击打开网址；指针移动超过 6px 时抑制误导航；锁定对象既不能拖动也不能键盘移动。
- 推挤找不到位置时自动降级为**局部重排**（固定拖动位与锁定对象，不改尺寸）；两者都失败才回滚并说明原因。
- **紧凑整理**：按阅读顺序向上、向左压缩整页空白，大对象先定位、锁定对象保持原位、不改变任何尺寸。必须先看预览（含影响对象数与页面高度变化）再确认，确认后仍只记一个撤销事务。
- **内置待办组件**：回车添加、勾选完成、删除、清除已完成，50 条与 120 字符上限。数据存在按实例隔离的本地存储中，**不进入 Workspace**——勾选一件事不会产生布局事务，也不会污染布局撤销栈。
- **Widget 宿主**：每个组件包在独立错误边界内，任一组件崩溃只渲染错误卡片并保留网格位置，时钟、搜索、图标与布局引擎继续可用。组件通过宿主拿到主题、语言、尺寸、减少动态效果与材质等级。
- **沙箱组件通道**：设置 → 数据 → 沙箱组件通道可查看真实握手。沙箱页无法访问父页面 DOM 与扩展 API；宿主校验消息来源、实例绑定、重放与频率，仅开放只读环境能力。
- 明暗主题、四档材质、减少动态效果、时间/时区/日历、搜索引擎和打开方式设置。
- Workspace v2 校验、IndexedDB 持久化、失败回滚、备份导入导出、本地壁纸与资源恢复。旧版 v1 数据在加载时自动增量迁移。
- 空快捷方式、损坏工作区恢复、原始数据导出、存储失败提示。
- 最小权限 Manifest；sandbox 父 DOM 与扩展 API 隔离，严格 CSP。

## 手动验收清单（阶段 4 重点）

自动化已验证 82 次，但以下属于**人工判断**，自动化替代不了。建议按顺序做一遍，每步都能独立回退。

### 准备：加载扩展

```bash
cd /Volumes/Cupcake/Workspace/glass-home
pnpm install        # 首次
pnpm build          # 必须，E2E 与手动都读 .output/chrome-mv3
```

Edge 打开 `edge://extensions` → 开启「开发者模式」→「加载解压缩的扩展」→ 选 `.output/chrome-mv3`。
新开一个标签页（或按新标签快捷键）即进入 Glass Home。

> 想用打包产物验证，可先在 `edge://extensions` 里卸载，再用 `.output/glass-home-0.1.0-chrome.zip` 解压后的目录加载——两者内容一致。

### ① 备份带回组件数据（基线 14.3）

1. 在待办里加 2 条，勾选其中 1 条。
2. 设置 → 数据 → **导出备份**，保存到桌面。
3. 打开该 JSON 文件，搜索 `widgetData`，应能看到 `"namespace": "builtin.todo"`。
4. 设置 → 数据 → **清除全部数据** → 二次确认 → 页面自动重载，待办应为空。
5. 设置 → 数据 → **导入备份**，选刚才那份 → 待办内容与勾选状态应**完全恢复**。

**判断点**：第 5 步恢复的是「2 条，其中 1 条已完成」，不是「2 条都未完成」。

### ② 清除单个组件（基线 12.4）

1. 待办里留几条内容。
2. 设置 → 数据 → 组件数据列表，「待办」那行应显示**真实占用**（不是 0 B）与「清除」按钮。
3. 点「清除」→ 二次确认 → 待办内容清空，但**待办组件本身还在原位**，周围图标位置不变。
4. 刷新页面，确认清空是持久的。

**判断点**：组件消失或位置变化都算失败——清除的是「数据」，不是「组件」。

### ③ 清除全部数据要真的清干净（基线 12.4）

1. 设置里换一张自定义壁纸。
2. 加点待办。
3. 设置 → 数据 → **清除全部数据** → 二次确认。
4. 页面重载后：壁纸回到默认渐变、待办为空、快捷方式回默认 20 个。

**判断点**：若壁纸还在，说明 `assets` 没被清；若待办还在，说明 `widget-data` 没被清。

### ④ 旧备份不能误删待办（最难发现的一类缺陷）

1. 先按 ① 的步骤 2 导出一份**当前**备份。
2. 用文本编辑器打开它，删除整个 `"widgetData": [...]` 字段（注意逗号），另存为 `legacy.json`。
3. 保留页面现有待办不受影响的前提下，导入 `legacy.json`。
4. **待办应仍然存在**。

**判断点**：这是一条数据丢失防线。「备份里没有这个字段」不等于「用户没有数据」，二者必须区分。

### ⑤ 沙箱通道（阶段 3 的既有缺陷修复）

设置 → 数据 → 滚到底部「沙箱组件通道」：

- 状态应为「已取得环境：深色 · zh-CN · balanced」，**不是**「沙箱未在时限内请求环境信息」。
- 下方小窗内显示主题/语言/尺寸/减少动态/材质五行。

**判断点**：曾经这里是稳定超时。若又出现超时，是回归。

### ⑥ 布局与键盘（阶段 2B 回归）

1. 进入编辑模式，用鼠标把一个图标拖到另一个图标上（交换）、拖到两图标之间（插入推挤）。
2. 拖动过程中按 `Esc`，布局应回滚且不写入本地。
3. `Tab` 选中对象后方向键移动一格、`Alt+方向键` 改尺寸，重排后焦点仍在该对象。
4. `Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 重做。

### ⑦ 视觉与无障碍（自动化无法判定）

- 四档材质（高/均衡/低/关闭）逐个切换，确认**差异真实可见**，关闭档应是实体表面而非仍带模糊。
- 浅色/深色 × 三种渐变壁纸，检查文字对比度是否够读。
- 系统开启「减少动态效果」后，拖动过渡动画应消失。
- 把窗口从 1440 拖到 1200、900、700 宽，检查是否出现横向滚动条。
- 全程纯键盘操作一遍，确认焦点不会丢失、不跑进被遮挡区域。

### 已知不算缺陷的现象

- 清除全部数据后会**整页重载**，此时正在编辑的未提交布局会丢——这是设计取舍。
- 待办勾选**不会**产生撤销记录（数据不进 Workspace，这是刻意的）。
- 撤销历史只保留在当前页面内，刷新即清空。

## 尚未实现 / 未验收

- **Widget 平台只开放只读环境能力**：网络代理 / Permission Broker、通知、书签、定位、实例存储写入均未开放给沙箱。
- 第三方 Widget 安装流程、刷新调度与后台 alarms、Widget 市场与签名分发未实现；当前只有硬编码的开发示例页。
- 整理功能只有"紧凑排列"一种模式；"保持分组"模式因默认布局尚无 `groupId` 而未实现。
- 多页面布局与 `expectedRevision` 冲突处理未实现（当前是单页面主屏幕）。
- Widget 指针拖拽尺寸手柄尚未实现；当前用 `Alt+方向键` 提供键盘尺寸调整。
- 拖动与待办操作的帧率未测量；产品基线中的 60fps 目标与持续拖动长任务检测尚未验收。
- 布局撤销历史只保留在当前页面内存中；普通快捷方式 CRUD 不提供实体级撤销，成功提交会清理旧布局历史。
- 独立图片图标上传、跨页面同步、横向多页、Dock、文件夹、账号与云同步。
- Chrome、Windows、Firefox、Safari 未实测；目前只有 macOS Edge 实测，不宣称跨浏览器支持。
- 发布级键盘与屏幕阅读器、完整壁纸对比度尚未验收。
- Workspace 已到 v2（v1 自动迁移）；后续 schema 变更需继续提供迁移。
